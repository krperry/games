Rolling a Die with Sound

In this lesson you will add the sound of dice rattling to your die roll program. If you did the coin lessons, this will feel familiar. It is the same idea you used to add sound to the coin flip. That is how programming often works: once you learn a trick, you can use it again and again.

Topics covered in this lesson

  • Reusing what you already know
  • Installing and importing playsound
  • The order of statements in a program

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

Sample Run

When you run the program, you hear dice rolling. When the sound stops, you hear a number from 1 to 6:

5

Getting Ready

This program uses the playsound module. If you have not installed it yet, type this at the command prompt:

pip install playsound

If that gives you errors, try pip install playsound==1.2.2.

The program plays the file dice.wav from a folder named sounds. The sounds folder must be in the same folder as your program, and you must run the program from that folder.

The Source Code for Sound Roll

Type this program and save it as sound_roll.py:

import random
import playsound as ps

ps.playsound("sounds/dice.wav")
print(f"{random.randint(1,6)}")

How the Program Works

The program has two import lines and then two lines that do the work.

import random
import playsound as ps

The first imports the random module so you can use randint(). The second imports the playsound module with the shorter name ps.

ps.playsound("sounds/dice.wav")

This plays the dice sound. playsound() waits until the sound is finished before the program goes on.

print(f"{random.randint(1,6)}")

This rolls the die and prints the result, just like in roll.py.

Order Matters

Python runs your statements from top to bottom. The sound line comes first, so the player hears the dice, and then hears the number. That is how a real dice roll works. You shake the dice, they land, and then you look.

If you swapped the two lines, the player would hear the number first and then the dice sound. The number would be read by the screen reader at the same time the sound starts, which is harder to hear, and the order would not make sense.

When you design a game for the ear, think about the order of events. Each sound or message should come at the moment it makes sense.

Summary

This program combined two things you already knew how to do. You learned that:

  • Once you know how to do something in one program, you can use it in others.
  • Python runs statements in order, from top to bottom.
  • The order of sounds and messages shapes how the game feels to the player.
