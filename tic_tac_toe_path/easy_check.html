An Easier Way to Check for a Winner

The check_winner() function from the last lesson works, but it is hard to follow. It uses slices with steps, a loop over the numbers 1, 2, 3, 4, and 7, and two different checks inside the loop. Could you be sure, just by reading it, that it checks all eight ways to win?

In this lesson you will rewrite check_winner() in a simpler way. Instead of working out the winning lines with math, you will just list them. The new version is shorter, easier to read, and easier to trust. The same sixteen tests, plus a new cat’s game test, prove that it still works.

Topics covered in this lesson

  • Tuples
  • Storing data instead of computing it
  • Looping over a list of tuples
  • Chained comparisons, like a == b == c
  • Sets and set()
  • Rewriting code and re-running tests

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

The Source Code for Easy Check

Type this program and save it as easy_check.py:

"""A method to test for a tic tac toe winner"""

game_state = ["X", 1, 2, 3, 4, 5, 6, 7, 8, 9, "X", 0]


def display_board():
    """this function displays the board"""
    print(f" {game_state[1]} | {game_state[2]} | {game_state[3]} ")
    print("---|---|---")
    print(f" {game_state[4]} | {game_state[5]} | {game_state[6]} ")
    print("---|---|---")
    print(f" {game_state[7]} | {game_state[8]} | {game_state[9]} ")


def check_winner():
    """checks for a winner
    prints who wins and set 'R' to restart game
    """
    winning_sets = [
        (1, 2, 3),
        (4, 5, 6),
        (7, 8, 9),
        (1, 4, 7),
        (2, 5, 8),
        (3, 6, 9),
        (1, 5, 9),
        (3, 5, 7),
    ]

    for check in winning_sets:
        if game_state[check[0]] == game_state[check[1]] == game_state[check[2]]:
            game_state[0] = "R"
            print(f"'{game_state[check[0]]}' wins")
            return

    # If more moves return
    if len(set(game_state[1:10])) > 2:
        return

    print("Cats game!")
    game_state[0] = "R"
    return

Listing the Winning Lines

    winning_sets = [
        (1, 2, 3),
        (4, 5, 6),
        (7, 8, 9),
        (1, 4, 7),
        (2, 5, 8),
        (3, 6, 9),
        (1, 5, 9),
        (3, 5, 7),
    ]

This is a list of the eight ways to win. Each one is a group of three square numbers. The first three are the rows, the next three are the columns, and the last two are the diagonals.

Read it with your screen reader. You can check each line against the board in your head: top row 1, 2, 3. Middle row 4, 5, 6. And so on. It is easy to be sure that all eight are there and that each one is right. That was very hard to do with the slices in the old version.

This is a powerful idea in programming: sometimes it is better to write down the answers than to work them out. When there are only a few cases, a list is often clearer than clever math.

Tuples

Each winning line is written in parentheses, like (1, 2, 3), not square brackets. That makes it a tuple, not a list. A tuple is like a list, but it cannot be changed after it is made. You cannot add items to it, remove items, or replace one.

>>> line = (1, 2, 3)
>>> line[0]
1
>>> line[0] = 5
Traceback (most recent call last):
  ...
TypeError: 'tuple' object does not support item assignment

You get items from a tuple by index, just like a list. Programmers use tuples for small groups of values that belong together and should not change. The winning lines of Tic Tac Toe never change, so tuples are a good fit.

Checking Each Line

    for check in winning_sets:
        if game_state[check[0]] == game_state[check[1]] == game_state[check[2]]:
            game_state[0] = "R"
            print(f"'{game_state[check[0]]}' wins")
            return

The for loop goes through the eight winning lines. Each time, check holds one tuple, such as (4, 5, 6).

check[0] is the first square number in the line, such as 4. So game_state[check[0]] is what is in that square. Read it from the inside out: first get the square number from the tuple, then get the mark from the board.

Chained Comparisons

game_state[check[0]] == game_state[check[1]] == game_state[check[2]]

Python lets you chain comparisons. a == b == c means “a equals b, and b equals c.” It is True only if all three are the same.

>>> "X" == "X" == "X"
True
>>> "X" == "X" == "O"
False
>>> 4 == 5 == 6
False

As before, empty squares hold their own numbers, so three empty squares are never equal, and only three matching marks can be a win.

When it finds a win, the function sets the game-over flag, announces the winner, and returns.

Checking for a Full Board with set()

    # If more moves return
    if len(set(game_state[1:10])) > 2:
        return

This line uses a set. A set is a collection, like a list, but it never holds the same value twice, and its items are in no particular order. set() turns a list into a set, which throws away any repeats.

>>> set(["X", "O", "X", "X", "O"])
{'O', 'X'}
>>> set(["X", 2, "O", 4, "X"])
{2, 4, 'O', 'X'}

Think about what this means for the board. If every square is filled, the board holds only "X" and "O", so the set has 2 items. If even one square is empty, its number is in the set too, so the set has 3 or more items.

So len(set(game_state[1:10])) > 2 means “there is at least one empty square.” If so, the game is not over, and the function returns. Otherwise, it is a cat’s game.

This is clever and short. It is also a little harder to understand than the list comprehension in the old version. Short code is not always clearer code. Which one do you find easier to follow by ear?

Running the Same Tests

The test code at the bottom is the same as in check_winner.py. That is the real reason tests are so valuable. You rewrote the most important function in the game, and you can tell it still works just by running the same tests and hearing the same results.

Changing how code is written without changing what it does is called refactoring. Tests are what make refactoring safe.

Summary

You rewrote the winner check to be simpler. You learned that:

  • Sometimes listing the cases is clearer than computing them.
  • A tuple is like a list that cannot be changed. It is written with parentheses.
  • a == b == c is True only when all three are equal.
  • A set holds each value only once. set() removes repeats from a list.
  • Refactoring means changing how code is written without changing what it does.
  • Re-running tests after a change tells you if you broke something.
