Tic Tac Toe Against the Computer

This is the biggest Tic Tac Toe program in the folder. It has menus. You can play against a friend or against the computer. You can choose to be X or O. And the computer has three difficulty levels: Easy, which follows a fixed list of moves; Strange, which picks at random; and Difficult, which tries to win and tries to block you.

Writing a computer player is one of the most interesting parts of making games. In this lesson you will see how a simple strategy, written as a list of rules, can make the computer play surprisingly well.

This program also has several real bugs, some of them hard to spot. The second half of the lesson is a guided bug hunt. Finding and fixing bugs in someone else’s code is one of the most valuable skills a programmer can have.

Topics covered in this lesson

  • Storing all of a game’s settings in one list
  • Menus that set up a game
  • Using the number of empty squares to decide whose turn it is
  • Conditional expressions: a if condition else b
  • pop(0) and the index() list method
  • A computer player with rules: win, block, center, corner, anywhere
  • A main loop with a restart
  • Tracing and fixing bugs

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

How to Play

When the game starts, it asks three questions:

  1. One or two players? Type 1, 2, or Q to quit.
  2. For one player: what difficulty? Type 1 for Easy, 2 for Strange, 3 for Difficult, or 4 to quit.
  3. For one player: do you want to be X or O? X always moves first.

Then you play. Type the number of an empty square:

  • Top row: 1, 2, 3
  • Middle row: 4, 5, 6
  • Bottom row: 7, 8, 9

After each game, the program asks if you want to play again.

    *  argument s:
    *  position = Where you want to put the piece*

    *  returns
    *  True for placed False for fail

    if game_state[position] not in ["X", "O"]:
        game_state[position] = mark
        return True
    return False

How the Program Is Organized

The program has thirteen functions. Here they are, grouped by job:

  • Setting up: choose_one_or_two(), choose_difficulty(), choose_xoro(), and reset_board().
  • Playing: play_turn(), player_input(), computer_choice(), difficult_pick(), and mark_spot().
  • Checking and showing: display_board() and check_winner().
  • Ending: restart_game().
  • Running everything: main().

You know display_board(), mark_spot(), and player_input() from earlier lessons. check_winner() is the simpler version from easy_check.py. This lesson covers the rest.

The first line is # Complete tic-tac-toe game""". It starts with #, so it is a comment, not a docstring. The three quotes at the end are probably left over from a docstring that was changed into a comment.

All the Settings in One List

# Game_state
# index:
# 0   Player  'X', or 'O'  player picked
# 1-9 Is the board
# 10  difficulty
# 11 number of players
game_state = ["X", 1, 2, 3, 4, 5, 6, 7, 8, 9, "X", 0]

The comments explain what each index holds. Index 0 is used for more than the comment says. It also holds "R" when a game is over and "Q" when the player wants to quit. Index 10 holds the difficulty as a number: 0 for Easy, 1 for Strange, and 2 for Difficult. Index 11 holds the number of players.

Putting everything in one list means every function can read and change any setting without passing arguments around. The cost is that you have to remember what each number means. game_state[11] == 2 is much harder to understand by ear than number_of_players == 2. In larger programs, you would use separate, well-named variables, or a dictionary or class, which you will learn about in the adventure game lessons.

The Main Function

Start reading at main(), since it runs everything:

def main():
    while game_state[0] != "Q":
        choose_one_or_two()
        choose_difficulty()
        choose_xoro()
        while game_state[0] not in ["Q", "R"]:
            display_board()
            play_turn()
            check_winner()
            restart_game()

There are two loops:

  • The outer loop runs once per game, until the player quits. It asks the setup questions.
  • The inner loop runs once per turn, until the game is over ("R") or the player quits ("Q"). It reads the board, lets someone move, checks for a winner, and, if the game just ended, asks about playing again.

The two return lines at the top are called guard clauses. They leave the function early when it has nothing to do: in a two-player game there is no difficulty to choose, and if the player already quit, there is nothing to ask. Guard clauses keep the rest of the function from being indented inside an if.

The menu is printed one option per line, which is easy to hear and easy to move through. The player types 1, 2, or 3, and the program stores 0, 1, or 2 in index 10, by subtracting 1.

Whose Turn Is It?

def play_turn():
    remaining = len([x for x in game_state[1:10] if x not in ["X", "O"]]) % 2

This is a clever line. The list comprehension makes a list of the empty squares, and len() counts them. Then % 2 gives the remainder after dividing by 2, which is 1 if the count is odd and 0 if it is even.

Why does that tell you whose turn it is? At the start, there are 9 empty squares, which is odd, and it is X’s turn. After X moves, there are 8, which is even, and it is O’s turn. After O moves, there are 7, odd again, and it is X’s turn. So:

  • An odd number of empty squares means it is X’s turn. remaining is 1.
  • An even number means it is O’s turn. remaining is 0.

The game never needs a separate variable to remember whose turn it is. It works it out from the board.

    if game_state[11] == 2 and remaining == 1:
        player_input("X")
    elif game_state[11] == 2 and remaining == 0:
        player_input("O")
    elif game_state[0] == "X" and remaining == 1:
        player_input("X")
    elif game_state[0] == "X" and remaining == 0:
        computer_choice("O")
    elif game_state[0] == "O" and remaining == 1:
        computer_choice("X")
    elif game_state[0] == "O" and remaining == 0:
        player_input("O")

These six cases cover every possibility:

  • Two players: X or O types a square, depending on the turn.
  • One player who chose X: the player moves on X’s turns, and the computer plays
  • One player who chose O: the computer plays X on X’s turns, and the player moves on O’s turns.

Easy: A Fixed List of Moves

test_moves = [1, 2, 3, 5, 6, 7, 8, 9, 4]
    if game_state[10] == 0:
        while test_moves:
            position = test_moves.pop(0)
            if mark_spot(position, mark):
                break

On Easy, the computer always tries squares in the same order, from the global list test_moves. A list counts as True while it has items, so the loop keeps going as long as there are moves left.

pop(0) removes and returns the first item of a list. You have seen pop() with no argument, which takes the last item. With an index, pop() takes the item at that index.

>>> moves = [1, 2, 3]
>>> moves.pop(0)
1
>>> moves
[2, 3]

The computer tries each square with mark_spot(). Here is where the True or False from mark_spot() finally pays off. If the square is free, mark_spot() marks it and returns True, and break ends the loop. If it is taken, mark_spot() returns False, and the loop tries the next square.

Because the computer always plays the same way, Easy is good for testing. The name test_moves suggests that is what it was made for. But it has a bug when you play more than one game, which you will find in the bug hunt.

Strange: A Random Free Square

    elif game_state[10] == 1:
        spot_indexes = [x for x in game_state[1:10] if x not in ["X", "O"]]
        position = random.choice(spot_indexes)
        mark_spot(position, mark)

The list comprehension gives the free squares, and the computer picks one at random. Since empty squares hold their own numbers, each item in the list is also the index to mark.

Difficult: Rules for Playing Well

difficult_pick() follows a list of rules, in order, and uses the first one that works:

  1. If the computer can win with one move, take that square.
  2. If the other player could win with one move, block that square.
  3. Take the center, square 5.
  4. Take a free corner, squares 1, 3, 7, or 9, at random.
  5. Take any free square.

This is a well-known strategy for Tic Tac Toe. A computer that follows it perfectly is very hard to beat. Rules like this, written in order of importance, are a simple but powerful way to build a computer player for many games.

The Conditional Expression

    oponent_mark = "X" if player_mark == "O" else "O"

This is a conditional expression. It picks one of two values in a single line. Read it as: “the opponent is X if the computer is O, otherwise O.” It does the same thing as:

    if player_mark == "O":
        oponent_mark = "X"
    else:
        oponent_mark = "O"

Here player_mark is the computer’s own mark. The variable name oponent_mark is missing a “p,” but Python does not mind, as long as it is spelled the same way everywhere.

Finding a Winning or Blocking Square

    for i in [1, 4, 7]:
        # Check to place a winning piece
        row = [game_state.index(x) for x in game_state[i : i + 3] if x != player_mark]
        if len(row) == 1 and game_state[row[0]] not in ["X", "O"]:
            mark_spot(row[0], player_mark)
            return row[0]

Take one row at a time. The list comprehension keeps every square in the row that is not the computer’s mark. If only one such square is left, and it is empty, then the computer has the other two, and taking this square wins.

game_state.index(x) is a list method that returns the index where a value first appears in the list:

>>> board = ["X", 1, 2, 3]
>>> board.index(2)
2
>>> board.index("X")
0

For an empty square, the value is its own number, so index() gives back the same number. That is a roundabout way to get it, and it causes trouble with marks, since index("X") finds the first X in the whole list, which might be index 0. The check game_state[row[0]] not in ["X", "O"] keeps that from causing a wrong move, but it is fragile.

The block check is the same, but it keeps squares that are not the opponent’s mark. If only one is left and it is empty, the opponent has the other two, so the computer takes it to block.

The function does the same for the columns and the two diagonals, then tries the center, then the corners, then anything. Each successful rule marks the square and returns its number, so computer_choice() can say it out loud.

Ending and Restarting

def restart_game():

    ...
    if choice.upper() == "N":

main() calls this after every turn. The guard clause returns right away unless check_winner() just set index 0 to "R", meaning the game is over. Then it asks about playing again. "Q" makes both loops in main() stop. "R" makes the inner loop stop, so the outer loop starts a new game.

The Bug Hunt

Now that you understand the program, it is time to find its bugs. Each one below was found by running the program and listening carefully. For each one, try to work out the cause yourself before reading the explanation.

Bug 1: Quitting Does Not Quit Right Away

Run the game and type Q at the very first question. You would expect the game to end. Instead, it asks Choose 'X', 'O', or (Q)uit. The same thing happens if you choose 4 to quit at the difficulty menu.

The cause is this line in choose_xoro():

    if game_state == "Q":

It compares the whole list with the string "Q". A list is never equal to a string, so this is always False, and the function always goes on to ask. It should be:

    if game_state[0] == "Q":

A missing [0] is very easy to miss by ear, because the line still sounds reasonable. When a guard clause does not seem to work, check exactly what it is comparing.

Bug 2: The Difficult Computer Misses a Diagonal

In the sample run, X had squares 3 and 5, and the computer did not block square 7. Here is the code that checks that diagonal:

    # up slope
    # check to place winning piece
    row = [game_state.index(x) for x in game_state[2:7:2] if x != player_mark]

The slice game_state[2:7:2] starts at index 2, jumps by 2, and stops before 7. That gives squares 2, 4, and 6. The real diagonal is squares 3, 5, and 7, which is game_state[3:8:2].

Two more slices are wrong in the same way. The column check uses game_state[i:9:3], and the down slope uses game_state[1:9:4]. Both stop before index 9, so they leave out square 9. For the right-hand column, the slice holds only squares 3 and 6. When X takes square 3, the computer thinks square 6 is the last free square in a line X almost owns, and “blocks” it. That is why its first move in the sample run was square 6 instead of the center. The stop for both should be 10.

Slices are a common source of off-by-one errors. You can test any slice in the shell with a simple list like list(range(10)), where every item is the same as its index:

>>> board = list(range(10))
>>> board[2:7:2]
[2, 4, 6]
>>> board[3:8:2]
[3, 5, 7]
>>> board[3:9:3]
[3, 6]
>>> board[3:10:3]
[3, 6, 9]

Bug 3: Easy Mode Crashes in the Second Game

Play a game on Easy, choose to play again, and play Easy again. Partway through the second game, the program crashes:

UnboundLocalError: cannot access local variable 'position' where it is not associated with a value

test_moves is a global list, and pop(0) removes moves from it for good. It is never refilled. In the second game, the list runs out. When the list is empty, the while test_moves: loop does not run at all, so position is never set. Then the print() line tries to use it, and Python stops with this error.

The error message is a good clue. Unbound means a variable name has no value yet. When you hear it, look for a path through the code that skips the line that sets the variable.

To fix it, give the computer a fresh copy of the moves each time, such as moves = test_moves[:] at the start of the Easy block, and pop from moves instead.

Bug 4: reset_board() Undoes Its Own Work

def reset_board():
    game_state[0] = "X"
    for i in range(10):
        game_state[i] = i

range(10) gives 0 through 9. So the loop also sets game_state[0] to 0, undoing the line just above it. It should be range(1, 10). This bug happens not to break anything, because choose_xoro() sets index 0 again in a one-player game, and two-player games never look at it. Bugs that do no harm today can still cause trouble when the code changes later.

Smaller Problems

  • In the last rule of difficult_pick(), the computer always marks "O", even when it is playing X. That line should use player_mark.
  • That same rule looks for free squares in all of game_state, not just the board, so it could pick index 10 or 11.
  • The difficulty prompt says Choose only 1, 2, or 3: but 4 is also allowed.
  • Several prompts have no space at the end, such as Choose 1,2,3, or 4, so the player’s answer runs into the prompt.

Summary

You studied a complete game with menus and a computer player, and you hunted its bugs. You learned that:

  • Guard clauses return early when a function has nothing to do.
  • Counting the empty squares, with % 2, tells you whose turn it is.
  • a if condition else b picks one of two values.
  • pop(0) takes the first item of a list. index() finds where a value is.
  • A computer player can follow a list of rules in order: win, block, center, corner, anything.
  • Always say the computer’s move out loud.
  • Comparing a whole list with a string is always False.
  • Test slices in the shell with list(range(10)).
  • UnboundLocalError means a variable was used on a path where it was never set.
  • Global lists that are used up do not refill themselves.
