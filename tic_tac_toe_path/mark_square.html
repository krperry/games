Letting Players Mark a Square

So far the program has marked squares by itself. In this lesson the players do it. You will write a function that places a mark on the board only if the square is empty, and a function that asks a player for a square and keeps asking until they choose one that is free.

Along the way you will learn one of Python’s most useful tools, the list comprehension, which builds a new list from an old one in a single line.

Topics covered in this lesson

  • Functions with parameters
  • Functions that return True or False
  • Slices
  • Converting numbers to strings with str()
  • List comprehensions with if
  • Checking input against a list of legal answers
  • Single quotes inside double-quoted strings

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

The Source Code for Mark Square

Type this program and save it as mark_square.py:

"""Create functions to mark and display a spot by a player"""

game_state = ["X", 1, 2, 3, 4, 5, 6, 7, 8, 9, "X", 0]


def display_board():
    """this function displays the board"""
    print(f" {game_state[1]} | {game_state[2]} | {game_state[3]} ")
    print("---|---|---")
    print(f" {game_state[4]} | {game_state[5]} | {game_state[6]} ")
    print("---|---|---")
    print(f" {game_state[7]} | {game_state[8]} | {game_state[9]} ")


def mark_spot(position, mark):
    """a function to place a 'X' or 'O' and checkk if it is legal.
    *  argument s:
    *  position = Where you want to put the piece*
    * mark 'X' or 'O'
    *  returns
    *  True for placed False for fail
    """
    if game_state[position] not in ["X", "O"]:
        game_state[position] = mark
        return True
    return False


def player_input(mark):
    """this asks a player for a position and loops until it is legal
    Use the mark_spot function
    """
    choice = input(f"Enter a position for '{mark}': ")
    while choice not in [str(x) for x in game_state[1:10] if x not in ["X", "O"]]:
        print("incorrect position")
        choice = input(f"Enter a position for '{mark}': ")
    mark_spot(int(choice), mark)
    print(f"You placed an '{mark}'  in square {int(choice)}")


display_board()
player_input("X")
display_board()
player_input("O")
display_board()

The program has three functions: display_board(), which you know from the last lesson, and two new ones, mark_spot() and player_input(). The last five lines use them to let X and O each take one turn.

mark_spot(): Placing a Mark

def mark_spot(position, mark):
    """a function to place a 'X' or 'O' and checkk if it is legal.
    ...
    """
    if game_state[position] not in ["X", "O"]:
        game_state[position] = mark
        return True
    return False

Two Parameters

This function has two parameters, position and mark, separated by a comma. When you call mark_spot(5, "X"), position gets 5 and mark gets "X". The order of the arguments in the call matches the order of the parameters in the def line.

A Longer Docstring

The docstring is several lines long. It explains what each parameter means and what the function returns. That is a good habit for any function that takes arguments. It has a couple of typos, “checkk” and “argument s,” which do not affect how the program runs.

Checking Before Changing

The if statement checks whether the square already holds an X or an O. If it does not, the square is empty, so the function puts the mark there.

Returning True or False

After placing the mark, the function says return True. If the square was taken, the if block is skipped, and the function reaches return False.

A function that returns True or False lets the code that called it know whether it worked. This program does not use the answer yet, but later programs do, such as the computer player in hard-tic.py, which uses it to find a square that is free.

Notice that return ends the function right away. When the square is empty, return True runs, and the function never gets to return False. That is why there is no else. It is not needed.

player_input(): Asking for a Square

def player_input(mark):
    choice = input(f"Enter a position for '{mark}': ")
    while choice not in [str(x) for x in game_state[1:10] if x not in ["X", "O"]]:
        print("incorrect position")
        choice = input(f"Enter a position for '{mark}': ")
    mark_spot(int(choice), mark)
    print(f"You placed an '{mark}'  in square {int(choice)}")

This function asks a player for a square. It is the familiar “ask until the answer is good” pattern, but this time the list of good answers is built fresh each time. Let’s take that long while line apart.

Quotes Inside a String

The prompt is f"Enter a position for '{mark}': ". The f-string uses double quotes, and inside it are single quotes around the mark. Single quotes inside double quotes are just ordinary characters, so the player hears Enter a position for 'X':. Depending on your settings, your screen reader may say “tick” or “apostrophe” around the X.

Slices

game_state[1:10] is a slice. A slice gives you a new list with part of the old one. The first number is where to start, and the second is where to stop. The stop index is not included.

>>> game_state = ["X", 1, 2, 3, 4, "X", 6, 7, 8, 9, "X", 0]
>>> game_state[1:10]
[1, 2, 3, 4, 'X', 6, 7, 8, 9]
>>> game_state[1:4]
[1, 2, 3]

So game_state[1:10] is just the nine board squares, without the settings at index 0, 10, and 11.

str()

str() turns a value into a string. The player types a string, such as "5", but the empty squares hold numbers, such as 5. To compare them, the program turns the numbers into strings.

>>> str(5)
'5'
>>> "5" == 5
False
>>> "5" == str(5)
True

List Comprehensions

Here is the heart of the line:

[str(x) for x in game_state[1:10] if x not in ["X", "O"]]

This is a list comprehension. It builds a new list by looping over another one, all inside square brackets. Read it in this order:

  1. for x in game_state[1:10]: go through each square.
  2. if x not in ["X", "O"]: keep only squares that are not taken.
  3. str(x): for each one you keep, put its string version in the new list.

So with an X in square 5, the result is ['1', '2', '3', '4', '6', '7', '8', '9']. That is the list of every square a player could legally type.

The same list could be built with a regular loop:

legal = []
for x in game_state[1:10]:
    if x not in ["X", "O"]:
        legal.append(str(x))

The list comprehension does the same thing in one line. Try both in the shell to hear that they give the same result.

List comprehensions are very common in Python, so it is worth getting used to them. When a long one is hard to follow by ear, try reading it in the order above: the for part first, then the if part, then the part at the front.

Why This Check Is So Good

Because the program checks the player’s answer against the list of free squares, every kind of mistake is caught by the same line:

  • A square that is taken, like 5, is not in the list.
  • A number that is not on the board, like 0 or 10, is not in the list.
  • A word, like five, or an empty answer, is not in the list.

Any of these makes the program say incorrect position and ask again. And by the time the loop ends, choice is sure to be a free square, so int(choice) cannot fail.

Placing the Mark

    mark_spot(int(choice), mark)
    print(f"You placed an '{mark}'  in square {int(choice)}")

int(choice) turns the string back into a number to use as an index. Then the program tells the player what happened. Confirming each move out loud is very helpful for players who cannot see the board change.

There are two spaces before in square. You probably cannot hear them, but they are a small typo.

Taking Turns

display_board()
player_input("X")
display_board()
player_input("O")
display_board()

The bottom of the program shows the board, lets X move, shows the board, lets O move, and shows the board again. Each function call is short and says what it does. In the next lesson you will put these turns in a loop so the game can go on until it is over.

Designing for the Ear

  • incorrect position tells the player they made a mistake, but not what to do next. A message like That square is taken or not on the board. Choose an empty square from 1 to 9. is more helpful.
  • The game could read the free squares out loud when the player makes a mistake. You already have the list, so this is easy: ", ".join(legal).

Summary

You let players mark the board, safely. You learned that:

  • A function can take several parameters, separated by commas.
  • A function can return True or False to say whether it worked.
  • return ends the function right away.
  • A slice, like game_state[1:10], gives you part of a list.
  • str() turns a number into a string.
  • A list comprehension builds a new list from an old one in one line, with an optional if to keep only some items.
  • Checking input against a list of legal answers catches every kind of mistake at once.
