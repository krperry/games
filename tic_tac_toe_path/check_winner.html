A Function to Check for a Winner

In no_functions.py, the code that checks for a winner was in the middle of the game loop, and continue caused some surprising bugs. In this lesson you will move that code into its own function, check_winner(), where return can stop the checking the moment a winner is found.

Then you will test the function. Instead of playing dozens of games by hand, the program sets up sixteen winning boards, one for every way X or O can win, and checks each one.

Topics covered in this lesson

  • Moving code into a function
  • Using return to leave a function early
  • A function with no return value
  • Testing every case
  • Replacing a global variable with a new list

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

The Source Code for Check Winner

Type this program and save it as check_winner.py:

"""A method to test for a tic tac toe winner"""

game_state = ["X", 1, 2, 3, 4, 5, 6, 7, 8, 9, "X", 0]


def display_board():
    """this function displays the board"""
    print(f" {game_state[1]} | {game_state[2]} | {game_state[3]} ")
    print("---|---|---")
    print(f" {game_state[4]} | {game_state[5]} | {game_state[6]} ")
    print("---|---|---")
    print(f" {game_state[7]} | {game_state[8]} | {game_state[9]} ")


def check_winner():
    """checks for a winner
    prints who wins and set 'R' to restart game
    """
    # first row check
    for i in [1, 2, 3, 4, 7]:
        # row check
        if i in [1, 4, 7] and game_state[i : i + 3] == [game_state[i]] * 3:
            print(f"'{game_state[i]}' wins")
            game_state[0] = "R"
            return
        # Column check
        if i < 4 and game_state[i:10:3] == [game_state[i]] * 3:
            print(f"'{game_state[i]}' wins!")
            game_state[0] = "R"
            return

    # now test         down slope
    if game_state[1:10:4] == [game_state[1]] * 3:
        print(f"'{game_state[1]}' wins!")
        game_state[0] = "R"
        return

    # now test up slope
    if game_state[3:8:2] == [game_state[3]] * 3:
        print(f"'{game_state[3]}' wins!")
        game_state[0] = "R"
        return

    # If more moves return
    if [x for x in game_state[1:10] if x not in ["X", "O"]]:
        return

    print("Cats game!")
    game_state[0] = "R"
    return

The program has two parts. First, it defines display_board() and check_winner(). Then, under the comment # X win tests, it runs the tests.

The check_winner() Function

The body of check_winner() is the winner-checking code from no_functions.py, with one important change: every continue is now a return.

    for i in [1, 2, 3, 4, 7]:
        # row check
        if i in [1, 4, 7] and game_state[i : i + 3] == [game_state[i]] * 3:
            print(f"'{game_state[i]}' wins")
            game_state[0] = "R"
            return

If the slices and the [game_state[i]] * 3 trick are new to you, go back to the no_functions.py lesson, which explains them.

return Leaves the Whole Function

continue only went back to the top of the for loop. return is much stronger. It ends the whole function right away, no matter how many loops it is inside. As soon as one winning line is found, the function announces it, sets the game-over flag, and stops. Nothing else in the function runs.

That fixes both bugs from no_functions.py:

  • A winner is announced only once, even if one move makes two lines.
  • After a win, the function never reaches the cat’s game check, so a winning last move is not also called a tie.

return with No Value

In mark_square.py, mark_spot() said return True or return False. Here the function just says return, with no value. That means “stop now, I have nothing to give back.” This function does its job by printing and by changing game_state[0], so it does not need to return anything.

The last line of the function is also a return. A function ends when it runs out of lines anyway, so that last return is not needed, but it does no harm.

The Cat’s Game Check

    # If more moves return
    if [x for x in game_state[1:10] if x not in ["X", "O"]]:
        return

    print("Cats game!")
    game_state[0] = "R"
    return

If there are free squares, the game is not over, so the function returns without saying anything. If there are none, it is a cat’s game.

Testing Every Case

Below the functions are the tests. Each test is three lines:

game_state = ["X", "X", "X", "X", 4, 5, 6, 7, 8, 9, "X", 0]
display_board()
check_winner()

The first line makes a whole new board where X has won. Here, squares 1, 2, and 3 are X, so this tests the top row. Then the board is read, and check_winner() should announce X.

Why Test Every Way to Win

There are eight ways to win, and two players, so there are sixteen tests. Each way to win uses a different slice, and each slice could have a mistake. If you only tested the top row, a typo in the diagonal slice would hide until someone happened to win that way in a real game.

The tests are grouped with comments: # rows and # columns. Notice that the last two tests in the “columns” group are really the diagonals. Comments can be wrong, too. Code is checked by Python, but comments are not, so it is worth keeping them up to date.

There is no test for a cat’s game in this file. The next lesson, easy_check.py, adds one. Can you think of any other case that is missing? What about a board where no one has won yet and there are free squares? The function should print nothing at all.

Replacing the Whole List

Each test says game_state = [...], which makes a brand new list and puts it in the global variable. The functions read game_state each time they are called, so they see the new board.

There is a difference between replacing a list and changing one item of it. game_state = [...] makes the variable hold a different list. game_state[0] = "R" changes an item inside the list it already holds. Both are fine here, but the difference will matter later, when you learn about functions that change their arguments.

Listening to Test Output

When you run this program, you hear sixteen boards. That is a lot of listening. You can make it quicker by checking only the result lines. Most screen readers let you search the output, or you can move through it a line at a time and skip the board lines.

An even better idea is to have the program check itself, so it only speaks up when something is wrong. That is one of the exercises.

Summary

You moved the winner check into a function and tested it. You learned that:

  • return ends a whole function at once, even from inside loops.
  • return with no value just means “stop now.”
  • Moving code into a function can fix bugs, not just tidy things up.
  • Good tests cover every case, especially the ones that use different code.
  • Comments can be wrong. Keep them up to date.
  • game_state = [...] replaces the list. game_state[0] = "R" changes an item in it.
