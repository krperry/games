Tic Tac Toe in a Window with PySide6

Every program so far has run in the command prompt, reading and writing lines of text. Most programs people use every day run in windows instead, with buttons, menus, and dialog boxes. In this lesson you will build a two-player Tic Tac Toe game in a window, with one button for each square, using a toolkit called PySide6.

Windowed programs work very differently from the programs you have written so far. Instead of running from top to bottom and asking questions with input(), they set up a window and then wait for the user to do something. This lesson also shows how to make those windows work with a screen reader, which takes some extra care.

This is an advanced lesson. It introduces classes, which are covered in more depth in the adventure game lessons.

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

Getting Ready

PySide6 does not come with Python. Install it with:

pip install PySide6

It is a large download, so it may take a minute or two.

PySide6 is the official Python version of Qt, a toolkit used to build programs on Windows, macOS, and Linux. Qt has good support for screen readers, because it connects to each system’s accessibility features: UI Automation and MSAA on Windows, and similar systems on Mac and Linux. That means NVDA, JAWS, Narrator, VoiceOver, and Orca can all read Qt windows, as long as the program gives them good information to read.

How to Play

When you run python pyside_tic_tac_toe.py, a window opens with the title “Tic Tac Toe.” It holds nine buttons in a three-by-three grid. Press Tab to move from button to button, and press Space or Enter to take a square. With a mouse, you can click instead. X goes first, and the players take turns.

When someone wins, or the board fills up, a message box opens. After you close it, another asks whether you want to play again. If you choose No, the program ends.

What It Sounds Like

When the window opens, your screen reader reads its title, “Tic Tac Toe.” As you Tab through the squares, it reads each one as a button. After you take a square, it reads the button again with its new text, X or O.

The empty buttons are harder to hear. Their text is only a space, so the screen reader has no name to read. Depending on your screen reader and its settings, you may hear the square number, which this program stores in each button’s description, or you may hear only “button.” Later in the lesson you will see how to make this much better.

The Source Code for PySide Tic Tac Toe

Type this program and save it as pyside_tic_tac_toe.py:

"""pyside6 GUI of Tic Tac Toe"""
import sys
from PySide6.QtWidgets import (
    QApplication,
    QMainWindow,
    QPushButton,
    QGridLayout,
    QVBoxLayout,
    QWidget,
    QMessageBox,
)

from PySide6.QtGui import QFont


class TicTacToe(QMainWindow):
    """Main class representing the Tic Tac Toe game window."""
    def __init__(self):
        """
        Initialize the TicTacToe object.

        Sets up the game window, initializes the game state, and creates the game board.

        Args:
            None
        """
        super().__init__()

        self.setWindowTitle("Tic Tac Toe")
        self.setGeometry(100, 100, 300, 300)

        self.current_player = "X"
        self.board = [" "] * 9

        self.central_widget = QWidget(self)
        self.setCentralWidget(self.central_widget)

        layout = QVBoxLayout(self.central_widget)

        self.buttons = []

        grid_layout = QGridLayout()

        i = 1
        for row in range(3):
            button_row = []
            for col in range(3):
                button = QPushButton(" ", self)
                button.setAccessibleDescription(f"{i}")
                i += 1

                button.setMinimumSize(100, 100)
                button.setFont(QFont("Arial", 20))
                button.clicked.connect(self.make_button_click_handler(row, col))
                button_row.append(button)
                grid_layout.addWidget(button, row, col)
            self.buttons.append(button_row)

        layout.addLayout(grid_layout)

    def make_button_click_handler(self, row, col):
        """
        Create a button click handler function.

        Args:
            row (int): The row index of the clicked button.
            col (int): The column index of the clicked button.

        Returns:
            function: The button click handler function.
        """
    
        def handler():
            self.on_button_click(row, col)

        return handler

    def on_button_click(self, row, col):
        """
        Handle button click events.

        Updates the game state when a button is clicked.

        Args:
            row (int): The row index of the clicked button.
            col (int): The column index of the clicked button.

        Returns:
            None
        """
        index = row * 3 + col

        if self.board[index] == " ":
            self.board[index] = self.current_player
            self.buttons[row][col].setText(self.current_player)
            self.central_widget.setFocus()
            self.buttons[row][col].setFocus()

            if self.check_winner():
                self.show_winner()
                print("before reset")
                self.reset_board()
            elif " " not in self.board:
                self.show_draw()
                self.reset_board()
            else:
                self.current_player = "O" if self.current_player == "X" else "X"

    def check_winner(self):
        """
        Check for a winning combination on the game board.

        Returns:
            bool: True if there is a winner, False otherwise.
        """
        winning_combinations = [
            (0, 1, 2),
            (3, 4, 5),
            (6, 7, 8),  # Rows
            (0, 3, 6),
            (1, 4, 7),
            (2, 5, 8),  # Columns
            (0, 4, 8),
            (2, 4, 6),  # Diagonals
        ]

        for combo in winning_combinations:
            if (
                self.board[combo[0]]
                == self.board[combo[1]]
                == self.board[combo[2]]
                != " "
            ):
                return True

        return False

    def show_winner(self):
        """
        Display a message box announcing the winner.

        Returns:
            None
        """
        winner = f"Player {self.current_player} wins!"
        # Create a QMessageBox
        msg_box = QMessageBox()
        msg_box.setWindowTitle("Winner!")
        msg_box.setText(winner)
        #        msg_box.setIcon(QMessageBox.Information)

        # Set the modal property to make the dialog modal
        msg_box.setModal(True)
        msg_box.exec_()

    def ask_play_again(self, title, message):
        """
        Display a message box asking if the players want to play again.

        Args:
            title (str): Title of the message box.
            message (str): Message to be displayed in the message box.

        Returns:
            bool: True if the players want to play again, False otherwise.
        """

    
        msg_box = QMessageBox()
        msg_box.setWindowTitle(title)
        msg_box.setText(message)
        msg_box.setStandardButtons(QMessageBox.Yes | QMessageBox.No)
        msg_box.setDefaultButton(QMessageBox.No)
        result = msg_box.exec()
        return result == QMessageBox.Yes

    def show_draw(self):
        """
        Display a message box announcing a draw.

        Returns:
            None
        """
        msg_box = QMessageBox()
        msg_box.setWindowTitle("It's a draw!")
        msg_box.setText("Better luck next time!")
        # Set the modal property to make the dialog modal
        msg_box.setModal(True)
        msg_box.exec_()

    def reset_board(self):
        """
        Reset the game board.

        Asks players if they want to play again. If yes, the game is reset; otherwise, the window is closed.

        Returns:
            None
        """

        if not self.ask_play_again("Restart Game?", "do you want to play again?"):
            sys.exit()
        i = 1
        for row in range(3):
            for col in range(3):
                self.buttons[row][col].setText(" ")
                self.buttons[row][col].setAccessibleDescription(f"{i}")
                i += 1
        self.board = [" "] * 9
        self.current_player = "X"
        self.setWindowTitle("Tic Tac Toe")


if __name__ == "__main__":
    app = QApplication(sys.argv)
    window = TicTacToe()
    window.show()
    sys.exit(app.exec())

Windows, Widgets, and the Event Loop

A program with windows, buttons, and other controls is said to have a graphical user interface, or GUI, which people pronounce “gooey.” Each control, such as a button, a text box, or the window itself, is called a widget.

The biggest difference from your earlier programs is who is in charge. A command-prompt program decides what happens next. It asks a question with input() and waits for exactly that answer. A GUI program sets up its window and then hands control to the user. The user might click any button, press any key, move the window, or close it. The program waits, and reacts to whatever happens.

Each thing the user does is called an event. A GUI program has an event loop, a loop inside the toolkit that waits for events and calls your code when one happens. This style is called event-driven programming.

So instead of a while loop that runs the game, this program has functions that say, “when this button is pressed, do this.” The toolkit calls them for you.

Importing Names Directly

import sys
from PySide6.QtWidgets import (
    QApplication,
    QMainWindow,
    QPushButton,
    QGridLayout,
    QVBoxLayout,
    QWidget,
    QMessageBox,
)

from PySide6.QtGui import QFont

from ... import ... brings specific names out of a module, so you can use them without the module name in front. After this, the program can write QPushButton instead of PySide6.QtWidgets.QPushButton.

PySide6 is a package, a module that contains other modules. QtWidgets is the part with windows and buttons, and QtGui has fonts, colors, and images.

The list of names is in parentheses, one per line, which is easy to move through with a screen reader. All Qt names start with Q.

Classes and Objects

class TicTacToe(QMainWindow):
    """Main class representing the Tic Tac Toe game window."""

This line starts a class. A class is a blueprint for making objects. An object bundles together data, called attributes, and functions that work on that data, called methods.

You have used objects all along. Every string is an object of the str class, and upper() is one of its methods. Every list is an object of the list class, with methods such as append() and pop(). Now you are making your own class.

The TicTacToe class describes the game window. It holds the board, the current player, and the buttons, and it has methods for handling clicks, checking for a winner, and resetting the game.

Inheriting from QMainWindow

The (QMainWindow) after the class name means TicTacToe inherits from QMainWindow. QMainWindow is Qt’s class for a program’s main window. It already knows how to have a title bar, be moved and resized, and be closed. By inheriting from it, TicTacToe gets all of that for free, and only adds what is special about this game.

The init() Method

    def __init__(self):
        super().__init__()

__init__(), with two underscores on each side, is a special method that runs automatically when a new object is made. It sets the object up. It is often called the constructor.

self

Every method’s first parameter is self. When a method is called, self is the object it was called on. Inside the class, self.current_player means “this window’s current player.” You do not pass self yourself. Python does it for you. When you write window.show(), Python calls show() with self set to window.

super()

super().__init__() calls the __init__() method of the class you inherited from, QMainWindow. That lets Qt set up the window part of the object before this class adds its own setup. Forgetting this line is a common mistake, and Qt will give an error if you leave it out.

Setting Up the Window

        self.setWindowTitle("Tic Tac Toe")
        self.setGeometry(100, 100, 300, 300)

        self.current_player = "X"
        self.board = [" "] * 9

setWindowTitle() sets the title that the screen reader reads when the window gets focus. setGeometry() places the window 100 pixels from the left and top of the screen, and makes it 300 pixels wide and 300 tall.

The next two lines make attributes. Any variable that starts with self. is stored in the object and can be used by every method. self.board is a list of nine strings, one per square, and a space means empty.

Notice that this board is different from the game_state list in the command-prompt games. It has only nine items, at indexes 0 through 8, and empty squares hold a space, not their own number.

Layouts: Arranging the Buttons

        self.central_widget = QWidget(self)
        self.setCentralWidget(self.central_widget)

        layout = QVBoxLayout(self.central_widget)

A QMainWindow needs one central widget that holds everything else. Here it is a plain QWidget, which is like an empty panel.

A layout arranges widgets for you. You do not have to work out where each button goes in pixels. QVBoxLayout stacks things vertically, one above the other. This program only puts one thing in it, the grid, but it makes it easy to add more later, such as a status line under the board.

Layouts also matter for people with low vision. Because the layout sizes everything for you, the window can grow and the buttons will grow with it. That works better with screen magnifiers and large-text settings than fixed sizes do.

        self.buttons = []

        grid_layout = QGridLayout()

QGridLayout arranges widgets in rows and columns, which is perfect for a game board.

Making the Buttons

        i = 1
        for row in range(3):
            button_row = []
            for col in range(3):
                button = QPushButton(" ", self)
                button.setAccessibleDescription(f"{i}")
                i += 1

                button.setMinimumSize(100, 100)
                button.setFont(QFont("Arial", 20))
                button.clicked.connect(self.make_button_click_handler(row, col))
                button_row.append(button)
                grid_layout.addWidget(button, row, col)
            self.buttons.append(button_row)

        layout.addLayout(grid_layout)

Two nested loops make nine buttons, three rows of three. For each button, the program:

  1. Makes a QPushButton whose text is a single space.
  2. Sets its accessible description to the square number, 1 through 9.
  3. Makes it at least 100 by 100 pixels, with a large 20-point font. Big buttons with big text are easier to see and easier to hit with the mouse.
  4. Connects its clicked signal to a handler. This is explained below.
  5. Adds it to a list for the row, and places it in the grid at its row and column.

After each row, the row’s list is added to self.buttons, so self.buttons is a list of lists, like the deck of cards in the card lessons. self.buttons[1][2] is the button in row 1, column 2, which is the middle row, right side.

The variable i counts from 1 to 9 as the buttons are made, the same order the squares are numbered in the console games.

Signals and Slots

                button.clicked.connect(self.make_button_click_handler(row, col))

In Qt, when something happens to a widget, it sends out a signal. A button sends its clicked signal when it is pressed, by mouse or keyboard. You connect a signal to a function, and Qt calls that function every time the signal is sent. A function connected to a signal is called a slot, or a handler.

This is how event-driven programming works in Qt. The program never waits for a click. It just says, “when this button is clicked, call this function,” and the event loop takes care of the rest.

Functions That Make Functions

The handler needs to know which button was clicked. But clicked does not tell it the row and column. So the program uses a method that makes a handler for each button:

    def make_button_click_handler(self, row, col):
        def handler():
            self.on_button_click(row, col)

        return handler

This method defines a function inside itself, called handler(), and returns it. It does not call handler(). Notice there are no parentheses after handler in the return line. It returns the function itself, so Qt can call it later.

The inner function remembers the row and col it was made with, even after make_button_click_handler() has finished. A function that remembers variables from the place it was made is called a closure. So each button gets its own handler, and each handler remembers its own button’s row and column. When the button is clicked, its handler calls on_button_click() with the right row and column.

Why Not Just Use the Loop Variables?

You might wonder why the program does not just write a function right inside the loop that uses row and col. The problem is that such a function would look up row and col when it is called, not when it is made. By the time anyone clicks, the loops have finished, and row and col are both 2. Every button would act like the bottom right square. Making the handler in a separate method gives each one its own copy of the values. This is a classic trap in GUI programming, so it is worth remembering.

Handling a Click

    def on_button_click(self, row, col):
        index = row * 3 + col

Row and Column to Index

The board is a flat list of nine, but the buttons are in rows and columns. This formula turns a row and column into a list index. Each row has three squares, so row 1 starts at index 3, and row 2 starts at index 6. Add the column to get the square:

  • Row 0, column 0 is index 0.
  • Row 1, column 2 is 1 times 3 plus 2, which is index 5.
  • Row 2, column 1 is 2 times 3 plus 1, which is index 7.

This is a very common trick whenever a grid is stored in a list.

Making the Move

        if self.board[index] == " ":
            self.board[index] = self.current_player
            self.buttons[row][col].setText(self.current_player)
            self.central_widget.setFocus()
            self.buttons[row][col].setFocus()

If the square is empty, the program puts the player’s mark in the board list and sets the button’s text to X or O. Changing the text is what the screen reader will read from now on. If the square is taken, nothing happens at all. That is a problem for screen reader users, who get no feedback. You will improve it in an exercise.

The two setFocus() lines move keyboard focus away from the button and then back to it. This is a trick to make the screen reader announce the button again, so the player hears the new X or O right away. Screen readers usually only announce a widget when focus moves to it, so changing the text alone might be silent.

Win, Draw, or Next Player

            if self.check_winner():
                self.show_winner()
                print("before reset")
                self.reset_board()
            elif " " not in self.board:
                self.show_draw()
                self.reset_board()

If the move won, the program announces the winner and offers a new game. If no empty squares are left, it is a draw. Otherwise, the turn passes to the other player, using a conditional expression, which you met in hard-tic.py.

The print("before reset") line prints to the command prompt, not the window. It was used while the program was being written, to check that this part of the code ran. Leftover debugging lines like this are common. They are harmless, but they should be removed when the program is done.

Checking for a Winner

    def check_winner(self):
        winning_combinations = [
            (0, 1, 2),
            (3, 4, 5),
            (6, 7, 8),  # Rows
            ...
        ]

        for combo in winning_combinations:
            if (
                self.board[combo[0]]
                == self.board[combo[1]]
                == self.board[combo[2]]
                != " "
            ):
                return True

        return False

This is the same idea as easy_check.py: a list of the eight winning lines and a loop that checks each one. The square numbers are 0 to 8 here, because this board starts at index 0.

There is one important difference. In this board, empty squares all hold a space, so three empty squares are equal to each other. The chained comparison ends with != " " to make sure the three matching squares are not all empty. a == b == c != " " means all three are the same, and they are not spaces.

The long condition is split over several lines inside parentheses, one part per line. That is much easier to follow with a screen reader than one long line.

Message Boxes

    def show_winner(self):
        winner = f"Player {self.current_player} wins!"
        # Create a QMessageBox
        msg_box = QMessageBox()
        msg_box.setWindowTitle("Winner!")
        msg_box.setText(winner)
        #        msg_box.setIcon(QMessageBox.Information)

        # Set the modal property to make the dialog modal
        msg_box.setModal(True)

A QMessageBox is a small dialog window with a message and an OK button. Screen readers read message boxes automatically when they open, title first and then the text, so they are a reliable way to tell the player something important.

Modal means the player must close the dialog before they can use the main window again. exec_() shows the dialog and waits until it is closed. In newer versions of PySide6, the preferred name is exec(), without the underscore. The old name still works.

The line that sets an icon is commented out. A comment can be used to turn off a line of code without deleting it.

Asking a Yes or No Question

    def ask_play_again(self, title, message):
        msg_box = QMessageBox()
        msg_box.setWindowTitle(title)
        msg_box.setText(message)
        msg_box.setStandardButtons(QMessageBox.Yes | QMessageBox.No)
        msg_box.setDefaultButton(QMessageBox.No)
        result = msg_box.exec()
        return result == QMessageBox.Yes

This message box has Yes and No buttons. The | symbol, a vertical bar, combines the two options. You will hear it called “bar” or “pipe.”

exec() returns which button was pressed. The method compares it with QMessageBox.Yes and returns True or False. The default button is No, so if the player just presses Enter, the answer is no.

Resetting the Board

    def reset_board(self):
        if not self.ask_play_again("Restart Game?", "do you want to play again?"):
            sys.exit()
        i = 1
        for row in range(3):
            for col in range(3):
                self.buttons[row][col].setText(" ")
                self.buttons[row][col].setAccessibleDescription(f"{i}")
                i += 1
        self.board = [" "] * 9
        self.current_player = "X"
        self.setWindowTitle("Tic Tac Toe")

If the players do not want to play again, sys.exit() ends the program right away. A gentler way in a Qt program is QApplication.quit() or self.close(), which let Qt close its windows and clean up first.

Otherwise, it blanks every button, empties the board, and makes it X’s turn again.

Starting the Program

if __name__ == "__main__":
    app = QApplication(sys.argv)
    window = TicTacToe()
    window.show()
    sys.exit(app.exec())
  1. Every Qt program needs exactly one QApplication object. It is passed sys.argv, the list of words typed on the command line, so Qt can read any options meant for it.
  2. TicTacToe() makes a new game window. This runs __init__().
  3. window.show() makes the window appear.
  4. app.exec() starts the event loop. It runs until the last window is closed, and returns a number that says whether the program ended normally. sys.exit() passes that number back to the command prompt.

Making It Better for Screen Readers

The program does a few good things for accessibility: buttons work from the keyboard, results are shown in message boxes that screen readers announce, and focus is moved to make the new mark heard. But the empty buttons are a real problem. Their text is a single space, so their accessible name is blank.

A screen reader identifies a widget mainly by its name. The description is extra information that some screen readers read after a pause, and others only read on request. Putting the square number in the description means many players will only hear “button.”

A much better approach is to give each button a full accessible name that includes both its position and what is in it, and to update the name whenever the square changes:

button.setAccessibleName(f"Square {i}, empty")

and after a move:

self.buttons[row][col].setAccessibleName(f"Square {index + 1}, {self.current_player}")

Now the player hears “Square 5, empty, button” or “Square 5, X, button.” You could even name the squares by position, such as “Top left, empty.”

Here are some other improvements:

  • When a square is already taken, tell the player. A short message box, or better, a status label under the board that says Square 5 is taken, keeps the player informed.
  • Put the current player in the window title, such as Tic Tac Toe - O's turn, so the player can hear it with their screen reader’s “read title” command.
  • Put the empty squares’ numbers on the buttons themselves, as the console games do. That helps sighted and low-vision players, too.

Summary

You built a windowed game with PySide6. You learned that:

  • GUI programs are event-driven. They set up widgets and then react to events.
  • A class is a blueprint for objects. __init__() sets up a new object, and self is the object a method was called on.
  • Inheriting from a class, such as QMainWindow, gives you all of its abilities. super().__init__() sets up that part.
  • Layouts arrange widgets for you and resize them with the window.
  • A signal, such as clicked, can be connected to a handler function.
  • A function defined inside another function can remember its variables. This is called a closure, and it gives each button its own handler.
  • row * 3 + col turns a grid position into a list index.
  • Message boxes are read automatically by screen readers.
  • Screen readers rely on a widget’s accessible name. Set it, and keep it up to date.
