Tic Tac Toe in a Window with wxPython

In the last lesson you built Tic Tac Toe in a window with PySide6. In this lesson you will build the same game with a different toolkit, wxPython. The two programs have the same class, the same methods, and the same game logic. Only the toolkit parts are different.

Seeing the same program written with two toolkits shows you which ideas belong to GUI programming in general, and which belong to one toolkit. It also gives you a choice. wxPython uses each operating system’s own buttons and windows, which many screen reader users find very dependable.

If you have not done the PySide6 lesson, read it first. This lesson explains what is different and does not repeat everything.

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

Getting Ready

Install wxPython with:

pip install wxPython

Notice the capital P in the name you install. In your program, you import it as plain wx.

How to Play

Run python wx_tic_tac_toe.py. A window titled “Tic Tac Toe” opens with nine buttons in a grid. Press Tab to move between buttons and Space to take a square. X goes first. When someone wins, or the board fills up, a dialog tells you, and then another asks whether to play again.

The Source Code for wx Tic Tac Toe

Type this program and save it as wx_tic_tac_toe.py:

"""WX GUI of Tic Tac Toe"""
import wx

class TicTacToe(wx.Frame):
    """Main class representing the Tic Tac Toe game window."""

    def __init__(self):
        """
        Initialize the TicTacToe object.

        Sets up the game window, initializes the game state, and creates the game board.

        Args:
            None
        """
        super().__init__(None, title="Tic Tac Toe", size=(300, 300))
        self.current_player = "X"
        self.board = [" "] * 9

        panel = wx.Panel(self)
        vbox = wx.BoxSizer(wx.VERTICAL)

        self.buttons = []

        grid_sizer = wx.GridSizer(3, 3, 5, 5)

        i = 1
        for row in range(3):
            button_row = []
            for col in range(3):
                button = wx.Button(panel, label=" ", size=(100, 100))
                button.Bind(wx.EVT_BUTTON, self.make_button_click_handler(row, col))
                button_row.append(button)
                grid_sizer.Add(button, 0, wx.EXPAND)
                i += 1

            self.buttons.append(button_row)

        vbox.Add(grid_sizer, proportion=1, flag=wx.EXPAND)
        panel.SetSizer(vbox)

    def make_button_click_handler(self, row, col):
        """
        Create a button click handler function.

        Args:
            row (int): The row index of the clicked button.
            col (int): The column index of the clicked button.

        Returns:
            function: The button click handler function.
        """
        def handler(event):
            self.on_button_click(row, col)

        return handler

    def on_button_click(self, row, col):
        """
        Handle button click events.

        Updates the game state when a button is clicked.

        Args:
            row (int): The row index of the clicked button.
            col (int): The column index of the clicked button.

        Returns:
            None
        """
        index = row * 3 + col

        if self.board[index] == " ":
            self.board[index] = self.current_player
            self.buttons[row][col].SetLabel(self.current_player)

            if self.check_winner():
                self.show_winner()
                self.reset_board()
            elif " " not in self.board:
                self.show_draw()
                self.reset_board()
            else:
                self.current_player = "O" if self.current_player == "X" else "X"

    def check_winner(self):
        """
        Check for a winning combination on the game board.

        Returns:
            bool: True if there is a winner, False otherwise.
        """
        winning_combinations = [
            (0, 1, 2),
            (3, 4, 5),
            (6, 7, 8),  # Rows
            (0, 3, 6),
            (1, 4, 7),
            (2, 5, 8),  # Columns
            (0, 4, 8),
            (2, 4, 6),  # Diagonals
        ]

        for combo in winning_combinations:
            if (
                self.board[combo[0]]
                == self.board[combo[1]]
                == self.board[combo[2]]
                != " "
            ):
                return True

        return False

    def show_winner(self):
        """
        Display a message box announcing the winner.

        Returns:
            None
        """
        winner = f"Player {self.current_player} wins!"
        dlg = wx.MessageDialog(self, winner, "Winner!", wx.OK)
        dlg.ShowModal()
        dlg.Destroy()

    def ask_play_again(self, title, message):
        """
        Display a message box asking if the players want to play again.

        Args:
            title (str): Title of the message box.
            message (str): Message to be displayed in the message box.

        Returns:
            bool: True if the players want to play again, False otherwise.
        """
        dlg = wx.MessageDialog(self, message, title, wx.YES_NO | wx.ICON_QUESTION)
        result = dlg.ShowModal()
        dlg.Destroy()
        return result == wx.ID_YES

    def show_draw(self):
        """
        Display a message box announcing a draw.

        Returns:
            None
        """
        dlg = wx.MessageDialog(
            self, "It's a draw!\nBetter luck next time!", "It's a draw!", wx.OK
        )
        dlg.ShowModal()
        dlg.Destroy()

    def reset_board(self):
        """
        Reset the game board.

        Asks players if they want to play again. If yes, the game is reset; otherwise, the window is closed.

        Returns:
            None
        """
        if not self.ask_play_again("Restart Game?", "Do you want to play again?"):
            self.Destroy()
        for row in range(3):
            for col in range(3):
                self.buttons[row][col].SetLabel(" ")
        self.board = [" "] * 9
        self.current_player = "X"

if __name__ == "__main__":
    # Start the application and display the Tic Tac Toe game window.
    app = wx.App(False)
    frame = TicTacToe()
    frame.Show(True)
    app.MainLoop()

The Same Shape as the PySide6 Version

Move through the program with your screen reader’s “next function” or search command, and you will find the same methods as in pyside_tic_tac_toe.py:

  • __init__() builds the window and the buttons.
  • make_button_click_handler() makes a handler for each button.
  • on_button_click() makes a move, checks for a win or draw, and switches players.
  • check_winner() checks the eight winning lines.
  • show_winner(), ask_play_again(), and show_draw() show dialogs.
  • reset_board() starts a new game or closes the window.

check_winner() is exactly the same in both programs, word for word. It does not use the toolkit at all. It only looks at self.board. Code that does not depend on the toolkit can move from one toolkit to another without changes. That is a good reason to keep game rules separate from the code that draws the window.

Importing wx

import wx

wxPython puts everything in one module, wx. Every class and constant starts with wx., such as wx.Button and wx.OK. The PySide6 version imported each name separately with from ... import. Both styles are common.

The Frame

class TicTacToe(wx.Frame):
    def __init__(self):
        super().__init__(None, title="Tic Tac Toe", size=(300, 300))

In wxPython, a top-level window is called a frame. TicTacToe inherits from wx.Frame, just as the PySide6 version inherited from QMainWindow.

This time super().__init__() gets arguments. The first, None, means this window has no parent window. It is the main window. The other two are keyword arguments: title="Tic Tac Toe" and size=(300, 300). A keyword argument gives the name of the parameter along with the value. That makes the call easy to understand when you hear it, because each value is labeled.

The size is a tuple of width and height. Tuples are explained in the easy_check.py lesson.

Panels and Sizers

        panel = wx.Panel(self)
        vbox = wx.BoxSizer(wx.VERTICAL)

        self.buttons = []

        grid_sizer = wx.GridSizer(3, 3, 5, 5)

A wx.Panel goes inside the frame and holds the controls. Panels also handle moving between controls with the Tab key, so putting controls on a panel is important for keyboard users.

What Qt calls a layout, wxPython calls a sizer. wx.BoxSizer(wx.VERTICAL) stacks things vertically, like QVBoxLayout. wx.GridSizer(3, 3, 5, 5) makes a grid with 3 rows and 3 columns, and a gap of 5 pixels between rows and between columns, like QGridLayout.

Making the Buttons

        i = 1
        for row in range(3):
            button_row = []
            for col in range(3):
                button = wx.Button(panel, label=" ", size=(100, 100))
                button.Bind(wx.EVT_BUTTON, self.make_button_click_handler(row, col))
                button_row.append(button)
                grid_sizer.Add(button, 0, wx.EXPAND)
                i += 1

            self.buttons.append(button_row)

        vbox.Add(grid_sizer, proportion=1, flag=wx.EXPAND)
        panel.SetSizer(vbox)

The loops are the same as the PySide6 version. For each button:

  • wx.Button(panel, label=" ", size=(100, 100)) makes a button on the panel, with a space for its label, at 100 by 100 pixels.
  • Bind() connects an event to a handler. wx.EVT_BUTTON is the event a button sends when it is pressed. This is the same idea as Qt’s button.clicked.connect().
  • grid_sizer.Add(button, 0, wx.EXPAND) puts the button in the next spot in the grid. wx.EXPAND makes the button grow to fill its spot.

Unlike the Qt grid, which was told the row and column of each button, the wx grid sizer just fills in the spots in order: left to right, top to bottom.

The variable i counts from 1 to 9, but it is never used. In the PySide6 version, it was used to set each button’s accessible description. Here that line is missing, so i is left over. You will put it to use in the exercises.

At the end, the grid is added to the vertical sizer, and the sizer is given to the panel. proportion=1 and flag=wx.EXPAND make the grid fill the window and grow when the window grows.

Event Handlers Get an Event

    def make_button_click_handler(self, row, col):
        def handler(event):
            self.on_button_click(row, col)

        return handler

This is the same closure trick as in the PySide6 version, which gives each button a handler that remembers its own row and column. If closures are new to you, see that lesson.

There is one difference. In wxPython, every event handler receives an event object as an argument. It holds details about what happened, such as which control sent it. So handler() has a parameter named event. The handler does not use it, but it must accept it, or wxPython will give an error when it calls the handler.

Handling a Click

    def on_button_click(self, row, col):
        index = row * 3 + col

        if self.board[index] == " ":
            self.board[index] = self.current_player
            self.buttons[row][col].SetLabel(self.current_player)
            ...

This is the same as the PySide6 version, but wxPython’s method is named SetLabel() instead of setText(). wxPython methods start with a capital letter, and Qt methods start with a lowercase one.

This version does not have the setFocus() trick. On Windows, wxPython buttons are real Windows buttons, and most screen readers notice when a focused native button’s label changes, so the new mark is usually read without any extra code. If your screen reader does not read it, adding self.buttons[row][col].SetFocus() after SetLabel() can help.

Dialogs

    def show_winner(self):
        winner = f"Player {self.current_player} wins!"
        dlg = wx.MessageDialog(self, winner, "Winner!", wx.OK)
        dlg.ShowModal()
        dlg.Destroy()

wx.MessageDialog is wxPython’s message box. Its arguments are the parent window, the message, the title, and the buttons. ShowModal() shows it and waits until it is closed.

dlg.Destroy() frees the dialog when you are done with it. In wxPython, you should always destroy a dialog after using it. Qt cleans up message boxes on its own.

    def ask_play_again(self, title, message):
        dlg = wx.MessageDialog(self, message, title, wx.YES_NO | wx.ICON_QUESTION)
        result = dlg.ShowModal()
        dlg.Destroy()
        return result == wx.ID_YES

wx.YES_NO | wx.ICON_QUESTION combines two options with the | symbol: Yes and No buttons, and a question icon. ShowModal() returns which button was pressed, and the method compares it with wx.ID_YES.

Notice that it saves the result before destroying the dialog. After Destroy(), you should not use the dialog anymore.

The draw message uses \n to put a line break in the message, so It's a draw! and Better luck next time! are on separate lines. Screen readers read both lines.

Resetting the Board

    def reset_board(self):
        if not self.ask_play_again("Restart Game?", "Do you want to play again?"):
            self.Destroy()
        for row in range(3):
            for col in range(3):
                self.buttons[row][col].SetLabel(" ")
        self.board = [" "] * 9
        self.current_player = "X"

If the players do not want to play again, self.Destroy() closes the window. When the last window is closed, the program ends.

Look carefully at what happens next. There is no return after self.Destroy(), so the method keeps going and clears all the buttons on the window that is closing. wxPython waits a moment before really destroying a frame, so this usually causes no error, but it is not what was meant. Adding return right after self.Destroy() makes the intent clear.

Starting the Program

if __name__ == "__main__":
    # Start the application and display the Tic Tac Toe game window.
    app = wx.App(False)
    frame = TicTacToe()
    frame.Show(True)
    app.MainLoop()

This matches the PySide6 version, step for step:

Step PySide6 wxPython
Make the application QApplication(sys.argv) wx.App(False)
Make the window TicTacToe() TicTacToe()
Show it window.show() frame.Show(True)
Run the event loop app.exec() app.MainLoop()

The False passed to wx.App tells wxPython not to send printed output to a separate window.

Accessibility in wxPython

wxPython uses the operating system’s own controls. On Windows, a wx.Button is a real Windows button, the same kind used in Windows itself. Screen readers have supported these controls for decades, which is a big strength.

The accessible name of a native button comes from its label. So in this program, the empty buttons have a label of a single space, and the screen reader has nothing to say but “button.” Unlike the PySide6 version, there is no description either. A player who cannot see the board has no way to tell the squares apart until they are taken.

The simplest fix is to put the square number in the label, the same way the console games show empty squares:

button = wx.Button(panel, label=str(i), size=(100, 100))

Then, when a square is taken, SetLabel() replaces the number with X or O. To check whether a square is empty, use self.board, not the label. This one change makes the game playable by ear, and it helps sighted players, too.

A larger font also helps players with low vision. You can set one on each button:

button.SetFont(wx.Font(20, wx.FONTFAMILY_DEFAULT, wx.FONTSTYLE_NORMAL, wx.FONTWEIGHT_BOLD))

PySide6 or wxPython?

Both are good choices for accessible programs. Here are some differences:

  • PySide6 draws its own widgets and connects them to accessibility systems. It has methods like setAccessibleName() that let you control exactly what a screen reader says.
  • wxPython uses the operating system’s own controls, so they behave just like other programs on that system. You control what is read mostly through labels.
  • Qt’s naming style is setText(). wxPython’s is SetLabel().
  • In Qt you connect() a signal. In wxPython you Bind() an event.

The game logic does not care which you use. If you keep your game rules in their own functions, like check_winner(), you can switch toolkits later.

Summary

You built the same game with a second toolkit. You learned that:

  • In wxPython, a window is a wx.Frame, and controls go on a wx.Panel.
  • Sizers arrange controls, like Qt’s layouts.
  • Bind() connects an event, such as wx.EVT_BUTTON, to a handler.
  • wxPython handlers receive an event object.
  • Dialogs are shown with ShowModal() and should be freed with Destroy().
  • Keyword arguments, like title="Tic Tac Toe", label each value in a call.
  • Native controls get their accessible name from their label, so never leave a label blank.
  • Code that does not use the toolkit, such as check_winner(), can be shared between toolkits.
