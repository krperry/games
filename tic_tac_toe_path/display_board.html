A Function to Display the Board

In the last lesson the same five lines that print the board were written out twice. In this lesson you will move those lines into a function named display_board(). Then, any time you want to show the board, you call the function with one short line.

Turning repeated code into a function is one of the most important skills in programming.

Topics covered in this lesson

  • Defining a function with def
  • Docstrings for functions
  • Calling a function more than once
  • Functions that use a global variable
  • Defining a function before you call it

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

The Source Code for Display Board

Type this program and save it as display_board.py:

"""Start of tic tac toe just display the board"""

game_state = ["X", 1, 2, 3, 4, 5, 6, 7, 8, 9, "X", 0]


def display_board():
    """this function displays the board"""
    print(f" {game_state[1]} | {game_state[2]} | {game_state[3]} ")
    print("---|---|---")
    print(f" {game_state[4]} | {game_state[5]} | {game_state[6]} ")
    print("---|---|---")
    print(f" {game_state[7]} | {game_state[8]} | {game_state[9]} ")


display_board()
game_state[4] = "X"
display_board()
game_state[4] = "X"

Defining display_board()

def display_board():
    """this function displays the board"""
    print(f" {game_state[1]} | {game_state[2]} | {game_state[3]} ")
    ...

The def line starts a function named display_board. The parentheses are empty, because this function does not need any arguments. The colon at the end means a block is coming.

All the lines under it that are indented four spaces are the function’s body. Listen to the indentation: the docstring and the five print() lines are all at four spaces. The blank lines after them, and display_board() at zero spaces, are no longer part of the function.

Defining a function does not run it. When Python reaches the def line, it just remembers the name display_board and the code in its body. Nothing is printed yet.

A Docstring for a Function

The first line of the body is a docstring: """this function displays the board""". A docstring right under a def line describes what that function does. Many code editors will read it to you when you use the function, and the help() function in the shell shows it too:

>>> help(display_board)
Help on function display_board in module __main__:

display_board()
    this function displays the board

Calling the Function

display_board()
game_state[4] = "X"
display_board()
game_state[4] = "X"

These four lines are the part of the program that actually runs. Each display_board() line calls the function. Python jumps into the function, runs its body from top to bottom, and then comes back to the line after the call.

So the program prints the board, marks square 4, and prints the board again. The last line marks square 4 again. It does not hurt anything, since square 4 already has an X, but it does nothing useful. It is probably left over from copying and pasting. You can delete it.

The Function Uses a Global Variable

display_board() reads game_state, but game_state is not made inside the function. It is made at the top of the file, outside any function. That makes it a global variable, and any function in the file can read it.

Because the function reads the list each time it is called, it always prints the board as it is right now. When the second call happens, square 4 has changed, so the second board has an X.

Order Matters: Define, Then Call

Python runs a file from top to bottom. The def must come before the first call. Try moving the first display_board() line above the def line and run the program. You will hear:

NameError: name 'display_board' is not defined

At that point in the file, Python has not yet seen the definition.

Why Functions Help

Compare this program with simple_display.py:

  • The board-printing code is written once instead of twice.
  • If you want to change how the board looks, such as the spoken version from the last lesson, you change it in one place, and every call uses the new look.
  • The bottom of the program reads almost like plain English: display the board, mark a square, display the board.
  • The function’s name says what the code does, which helps when you move through a file with a screen reader. You can jump from def to def to find your way around.

Summary

You turned repeated code into a function. You learned that:

  • def name(): defines a function. Its body is the indented lines under it.
  • A docstring under the def line describes the function.
  • Calling a function runs its body and then comes back.
  • A function can read a global variable, and it sees its current value.
  • A function must be defined before it is called.
