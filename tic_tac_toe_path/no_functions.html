A Whole Game of Tic Tac Toe Without Functions

This program is a complete two-player game of Tic Tac Toe. Players take turns, the board is read after every move, and the game knows when someone has won or when the board is full. It is written all in one piece, from top to bottom, with no functions of its own.

Writing it this way is a good way to see the whole game at once. It also shows why functions are so helpful, because by the end you will hear the same lines repeated, and you will notice a tricky bug that comes from using continue inside a loop inside another loop.

Topics covered in this lesson

  • A game loop with while True:
  • Switching between two players
  • Checking rows, columns, and diagonals with slices
  • Slices with a step
  • Comparing a slice with a repeated list
  • continue in nested loops
  • Ending the game with a flag and quit()
  • Checking for a full board

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

How to Play Tic Tac Toe

Two players take turns. X goes first. On your turn, you type the number of an empty square, from 1 to 9, to put your mark there. The squares are numbered from the top left, like a phone keypad:

  • Top row: 1, 2, 3
  • Middle row: 4, 5, 6
  • Bottom row: 7, 8, 9

The first player to get three marks in a row, across, down, or corner to corner, wins. If all nine squares are full and no one has won, it is a tie, sometimes called a “cat’s game.”

The Source Code for No Functions

Type this program and save it as no_functions.py:

game_state = ["X", 1, 2, 3, 4, 5, 6, 7, 8, 9, "X", 0]

# display
print(f" {game_state[1]} | {game_state[2]} | {game_state[3]} ")
print("---|---|---")
print(f" {game_state[4]} | {game_state[5]} | {game_state[6]} ")
print("---|---|---")
print(f" {game_state[7]} | {game_state[8]} | {game_state[9]} ")


player = "O"
while True:
    # check to see if the game is over
    if game_state[0] == "R":
        quit()

    if player == "X":
        player = "O"
    else:
        player = "X"

    # get input
    choice = input(f"Enter a position for '{player}': ")
    while choice not in [str(x) for x in game_state[1:10] if x not in ["X", "O"]]:
        print("incorrect position")
        choice = input(f"Enter a position for '{player}': ")
    game_state[int(choice)] = player
    print(f"You placed an '{player}'  in square {int(choice)}")

    # display
    print(f" {game_state[1]} | {game_state[2]} | {game_state[3]} ")
    print("---|---|---")
    print(f" {game_state[4]} | {game_state[5]} | {game_state[6]} ")
    print("---|---|---")
    print(f" {game_state[7]} | {game_state[8]} | {game_state[9]} ")

    # Check for winnner
    # first row check
    for i in [1, 2, 3, 4, 7]:
        # row check
        if i in [1, 4, 7] and game_state[i : i + 3] == [game_state[i]] * 3:
            print(f"'{game_state[i]}' wins")
            game_state[0] = "R"
            continue
        # Column check
        if i < 4 and game_state[i:10:3] == [game_state[i]] * 3:
            print(f"'{game_state[i]}' wins!")
            game_state[0] = "R"
            continue

    # now test         down slope
    if game_state[1:10:4] == [game_state[1]] * 3:
        print(f"'{game_state[1]}' wins!")
        game_state[0] = "R"
        continue

    # now test up slope
    if game_state[3:8:2] == [game_state[3]] * 3:
        print(f"'{game_state[3]}' wins!")
        game_state[0] = "R"
        continue

    # If more moves continue
    if [x for x in game_state[1:10] if x not in ["X", "O"]]:
        continue

    print("Cats game!")
    game_state[0] = "R"
    continue

The Plan

The program follows this plan:

  1. Read the empty board.
  2. Repeat forever:
    1. If the game is over, quit.
    2. Switch to the other player.
    3. Ask the player for a free square and mark it.
    4. Read the board.
    5. Check for a win. If someone won, say so and mark the game as over.
    6. If the board is full, say it is a cat’s game and mark the game as over.

Starting the Game

The program first prints the empty board with the same five lines you know from simple_display.py. Then:

player = "O"
while True:

player holds whose turn it is. It starts as "O", which seems odd, since X goes first. You will see why in a moment.

while True: starts a loop that runs forever. The program will stop it from inside.

Is the Game Over?

    # check to see if the game is over
    if game_state[0] == "R":
        quit()

Index 0 of game_state is used as a flag. When the game ends, the program puts "R" there. At the top of each turn, it checks the flag. If it is "R", quit() ends the program.

quit() is built into Python and works like sys.exit(), which you saw in Rock, Paper, Scissors. sys.exit() is the better choice in real programs, because quit() is meant for the interactive shell, but both work here.

Switching Players

    if player == "X":
        player = "O"
    else:
        player = "X"

At the start of every turn, the player switches. If it was X, it becomes O, and if it was O, it becomes X. Because player started as "O", the very first switch makes it "X", so X goes first. That is why it started as O.

Getting the Move

    choice = input(f"Enter a position for '{player}': ")
    while choice not in [str(x) for x in game_state[1:10] if x not in ["X", "O"]]:
        print("incorrect position")
        choice = input(f"Enter a position for '{player}': ")
    game_state[int(choice)] = player
    print(f"You placed an '{player}'  in square {int(choice)}")

This is the same code as player_input() from mark_square.py, but written right here instead of in a function. It keeps asking until the player types a free square, marks it, and says what happened. If the list comprehension is new to you, go back to the mark_square.py lesson.

Then the five board lines are printed again.

Checking for a Winner

There are eight ways to win: three rows, three columns, and two diagonals. The program checks them with slices.

Slices with a Step

You know that game_state[1:4] gives the items at indexes 1, 2, and 3. A slice can also have a third number, called the step. It says how far to jump each time. game_state[1:10:3] starts at 1, jumps by 3, and stops before 10, giving indexes 1, 4, and 7. That is the left column.

>>> board = ["-", 1, 2, 3, 4, 5, 6, 7, 8, 9]
>>> board[1:4]
[1, 2, 3]
>>> board[1:10:3]
[1, 4, 7]
>>> board[1:10:4]
[1, 5, 9]
>>> board[3:8:2]
[3, 5, 7]

With slices you can grab any line on the board:

  • Rows start at 1, 4, or 7 and take three in a row: [i : i + 3].
  • Columns start at 1, 2, or 3 and jump by 3: [i:10:3].
  • The diagonal from top left to bottom right is 1, 5, 9: [1:10:4].
  • The diagonal from top right to bottom left is 3, 5, 7: [3:8:2].

Is the Line All the Same?

To check whether a line is a win, the program compares the slice with a list of three copies of its first square:

game_state[i : i + 3] == [game_state[i]] * 3

If square 1 holds "X", then [game_state[1]] * 3 is ["X", "X", "X"]. If the slice is also ["X", "X", "X"], the row is a win.

What about an empty row? Its slice might be [1, 2, 3], and the list of copies would be [1, 1, 1]. Those are not equal, so an empty row is never a win. That is why the empty squares hold their own numbers instead of a blank. No two empty squares can ever match.

The Row and Column Loop

    for i in [1, 2, 3, 4, 7]:
        # row check
        if i in [1, 4, 7] and game_state[i : i + 3] == [game_state[i]] * 3:
            print(f"'{game_state[i]}' wins")
            game_state[0] = "R"
            continue
        # Column check
        if i < 4 and game_state[i:10:3] == [game_state[i]] * 3:
            print(f"'{game_state[i]}' wins!")
            game_state[0] = "R"
            continue

Rows start at 1, 4, and 7. Columns start at 1, 2, and 3. Put together, that is 1, 2, 3, 4, and 7, so the loop goes through those five numbers. For each one:

  • If it is the start of a row, check the row.
  • If it is less than 4, it is the start of a column, so check the column.

Square 1 starts both a row and a column, so both checks run for it.

A Bug: continue Only Affects the Inner Loop

When the program finds a winner, it says so, sets the flag, and calls continue. But continue goes back to the top of the loop it is directly inside. That is the for loop, not the while loop. So the program goes on to the next i and keeps checking.

Usually that does no harm. But if one move makes two lines at once, such as the top row and the right-hand column, the program announces the winner twice: once when i is 1 and once when i is 3. And even after one win, it goes on to check the diagonals and the full board.

What was probably meant was “stop checking, the game is over.” When you split this code into a function in the next lessons, return does exactly that.

The Diagonals

    # now test         down slope
    if game_state[1:10:4] == [game_state[1]] * 3:
        print(f"'{game_state[1]}' wins!")
        game_state[0] = "R"
        continue

    # now test up slope
    if game_state[3:8:2] == [game_state[3]] * 3:
        print(f"'{game_state[3]}' wins!")
        game_state[0] = "R"
        continue

These check the two diagonals. Here, continue is inside the while loop directly, so it jumps to the top of the game loop, where the flag is checked and the program quits.

A Cat’s Game

    # If more moves continue
    if [x for x in game_state[1:10] if x not in ["X", "O"]]:
        continue

    print("Cats game!")
    game_state[0] = "R"
    continue

The list comprehension makes a list of the free squares. An empty list counts as False, and a list with anything in it counts as True. So this means: if there are any free squares, keep playing. Otherwise, the board is full, and it is a cat’s game.

There is one more problem here. If the last move fills the board and wins, the game will say the player wins and then also say Cats game!, because the win check above did not stop the program from getting here.

Summary

You wrote a whole game in one piece. You learned that:

  • A slice can have a step: [start:stop:step].
  • Slices make it easy to grab rows, columns, and diagonals.
  • [value] * 3 makes a list of three copies, which is handy for comparing.
  • Empty squares that hold different numbers can never look like a win.
  • continue affects only the loop it is directly inside.
  • A flag in the game’s data can tell the game loop when to stop.
  • An empty list counts as False.
  • Long programs with no functions repeat code and are hard to follow.
