Printing the Tic Tac Toe Board

You have a list that holds the board. Now you need to show it to the player. In this lesson you will print the board as three rows, mark a square, and print it again so you can hear the change.

You will also notice something important: the same five lines of code appear twice. That repetition is a problem you will solve in the next lesson.

Topics covered in this lesson

  • Printing a board with f-strings
  • Getting list items by index inside an f-string
  • Changing a list item
  • How a board sounds with a screen reader
  • Noticing repeated code

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

Sample Run

 1 | 2 | 3
---|---|---
 4 | 5 | 6
---|---|---
 7 | 8 | 9
 1 | 2 | 3
---|---|---
 X | 5 | 6
---|---|---
 7 | 8 | 9

The first board is empty. In the second, square 4 has an X.

The Source Code for Simple Display

Type this program and save it as simple_display.py:

game_state = ["X", 1, 2, 3, 4, 5, 6, 7, 8, 9, "X", 0]

print(f" {game_state[1]} | {game_state[2]} | {game_state[3]} ")
print("---|---|---")
print(f" {game_state[4]} | {game_state[5]} | {game_state[6]} ")
print("---|---|---")
print(f" {game_state[7]} | {game_state[8]} | {game_state[9]} ")


game_state[4] = "X"

print(f" {game_state[1]} | {game_state[2]} | {game_state[3]} ")
print("---|---|---")
print(f" {game_state[4]} | {game_state[5]} | {game_state[6]} ")
print("---|---|---")
print(f" {game_state[7]} | {game_state[8]} | {game_state[9]} ")

Printing One Row

print(f" {game_state[1]} | {game_state[2]} | {game_state[3]} ")

This f-string has three sets of curly braces. Each one holds a list item by its index. Python fills in the value of each square, so for an empty board it prints 1 | 2 | 3.

The vertical bar, |, draws a line between the squares on screen. There is a space on each side of every square so the board is easier to read.

Printing the Lines Between Rows

print("---|---|---")

This is a plain string with no f, because there is nothing to fill in. It draws a line under the row.

How the Board Sounds

On a screen, these lines draw a grid. With a screen reader, the experience is different. Depending on your settings, a row may be read as “1 bar 2 bar 3,” and the line between rows may be read as “dash dash dash bar dash dash dash bar dash dash dash,” or skipped completely.

The row lines are useful. As you move up and down by line, each row is one line, and you can hear the three squares in order. The dividing lines are not useful by ear. They make you press the down arrow an extra time for each row.

Here is a board that is easier to hear. Each row is one line, and there are no divider lines:

print(f"Top row: {game_state[1]}, {game_state[2]}, {game_state[3]}")
print(f"Middle row: {game_state[4]}, {game_state[5]}, {game_state[6]}")
print(f"Bottom row: {game_state[7]}, {game_state[8]}, {game_state[9]}")

With commas between the squares, your screen reader pauses a little between each one. Saying “Top row,” “Middle row,” and “Bottom row” tells the player where they are. You will try this in the exercises.

A good game might offer both: a drawn board for players who look at the screen, and a spoken board for players who listen.

Marking a Square

game_state[4] = "X"

This puts an "X" in square 4, replacing the number 4. Then the program prints the board again with the exact same five lines, and you can hear the X in the middle row.

Repeated Code

The five print() lines that draw the board appear twice in this program. That works, but it causes problems:

  • If you want to change how the board looks, you must change it in two places. It is easy to forget one.
  • A real game prints the board after every move. You would need those five lines nine times or more.
  • The program is longer and harder to move through with a screen reader.

Whenever you notice yourself copying the same lines, that is a sign that they should be a function. In the next lesson, display_board.py, you will do exactly that.

Summary

You printed a Tic Tac Toe board and changed a square. You learned that:

  • An f-string can hold several list items, each in its own curly braces.
  • A board drawn with lines and bars works on screen but can be noisy by ear.
  • Labels and commas make a board easier to hear.
  • Code that is repeated is a sign you need a function.
