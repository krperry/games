Checking the Player’s Choice

Many games give the player a menu: press 1 for this, 2 for that, 3 for something else. Before a game acts on a choice, it should check that the choice is one it knows about. In this short lesson you will ask the player to choose, check the answer, and respond.

This little program also shows a mistake that is very common and very easy to miss by ear: forgetting the f on an f-string.

Topics covered in this lesson

  • Getting a menu choice with input()
  • Checking a choice with in
  • if and else
  • Why the numbers in the list are strings
  • The missing f mistake

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

Sample Runs

If the player types 2:

Enter your choice 1, 2, or 32
Your choice was: 2

If the player types 7:

Enter your choice 1, 2, or 37
7 was not one of the choices

The Source Code for Input Choice

Type this program and save it as input_choice.py:

choice = input("Enter your choice 1, 2, or 3")

if choice in ["1", "2", "3"]:
    print(f"Your choice was: {choice}")
else:
    print(f"{choice} was not one of the choices")

Asking for a Choice

choice = input("Enter your choice 1, 2, or 3")

input() shows the prompt and returns what the player types, as a string. The string is stored in choice.

The prompt has no space or colon at the end. When the player types 2, the line reads Enter your choice 1, 2, or 32. A sighted player might see the cursor and understand, but a screen reader user hears “1, 2, or 32,” which is confusing. Always end a prompt with a colon and a space, such as "Enter your choice 1, 2, or 3: ".

Checking the Choice

if choice in ["1", "2", "3"]:

The in operator checks whether choice is one of the items in the list.

Why Are the Numbers in Quotes?

The list holds "1", "2", and "3", which are strings, not the numbers 1, 2, and 3. That is on purpose. input() always returns a string. The string "2" and the number 2 are not equal:

>>> "2" == 2
False
>>> "2" in [1, 2, 3]
False
>>> "2" in ["1", "2", "3"]
True

By comparing strings with strings, the program never has to convert the answer to a number. It also means that if the player types something that is not a number at all, like cat, nothing breaks. "cat" is simply not in the list.

The Two Messages

    print(f"Your choice was: {choice}")
else:
    print(f"{choice} was not one of the choices")

If the choice is in the list, the first print() runs. Otherwise, the else block runs.

Both Strings Need the f

Both print() lines use f-strings, so {choice} is replaced with what the player typed. An earlier version of this program left the f off the second line:

    print("{choice} was not one of the choices")

Without the f, Python does not fill in the curly braces. It prints them as plain characters, so the player heard “left brace choice right brace was not one of the choices” instead of the number they typed.

This mistake is easy to make and easy to miss, because the two lines sound almost the same. With a screen reader, it helps to listen to the first few characters of each string, or to search your code for print(" lines that contain a brace. If you ever hear a brace in your program’s output, look for a missing f.

Summary

You checked a player’s menu choice. You learned that:

  • in checks whether a value is in a list.
  • input() returns a string, so compare it with strings like "1", not numbers like 1.
  • A prompt should end with a colon and a space.
  • If you hear curly braces in your output, you probably forgot the f in an f-string.

Exercises

  1. Take the f off the second print() line and run the program with a bad choice. Listen to what the player hears. Then put the f back.
  2. Add a colon and a space to the end of the prompt.
  3. Make the menu clearer. Before the input() line, print three lines that say what each choice means, such as 1. Play a game, 2. Hear the rules, and 3. Quit.
  4. Use a while loop so the program keeps asking until the player types 1, 2, or 3.
  5. Use if and else with == so the program says something different for each choice. Hint: if you know about elif, use it. If not, you will learn it in the Rock, Paper, Scissors lesson.
