Rock, Paper, Scissors

In this lesson you will write a complete game of Rock, Paper, Scissors against the computer. The game keeps score, lets you play as many rounds as you like, and counts “1, 2, 3” with dramatic pauses before the computer shows its move.

This is the first game in these lessons with its code inside a main() function. It also uses elif to choose between more than two options, and and to combine conditions.

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

How to Play Rock, Paper, Scissors

Each player picks rock, paper, or scissors at the same time.

  • Rock breaks scissors, so rock wins.
  • Scissors cut paper, so scissors win.
  • Paper covers rock, so paper wins.
  • If both players pick the same thing, it is a tie.

The Source Code for Rock, Paper, Scissors

Type this program and save it as rps.py. It does not use sound files, so it can go in any folder.

"""Rock, Paper, Scissors"""
import random
import time
import sys


def main():
    """Main game function"""
    # Scoring variables
    wins = 0
    losses = 0
    ties = 0

    while True:  # Main game loop.
        player_move = ""
        while player_move not in ["R", "P", "S"]:
            if player_move:
                print("Type one of R, P, S, or Q.")
            else:
                print(f"{wins} Wins, {losses} Losses, {ties} Ties")
                print("Enter your move: (R)ock (P)aper (S)cissors or (Q)uit")
            player_move = input("> ").upper()
            if player_move == "Q":
                print("Thanks for playing!")
                sys.exit()

        # Display what the player chose:
        if player_move == "R":
            print("ROCK versus...")
            player_move = "ROCK"
        elif player_move == "P":
            print("PAPER versus...")
            player_move = "PAPER"
        elif player_move == "S":
            print("SCISSORS versus...")
            player_move = "SCISSORS"
        # Count to three with dramatic pauses:
        time.sleep(0.5)
        print("1...")
        time.sleep(0.25)
        print("2...")
        time.sleep(0.25)
        print("3...")
        time.sleep(0.25)
        # Display what the computer chose:
        computer_move = random.choice(["ROCK", "PAPER", "SCISSORS"])
        print(computer_move)
        time.sleep(0.5)
        # Display and record the win/loss/tie:
        if player_move == computer_move:
            print("It's a tie!")
            ties = ties + 1
        elif True in [
            (player_move == "ROCK" and computer_move == "SCISSORS"),
            (player_move == "PAPER" and computer_move == "ROCK"),
            (player_move == "SCISSORS" and computer_move == "PAPER"),
        ]:
            print("You win!")
            wins = wins + 1
        else:
            print("You lose!")
            losses = losses + 1


if __name__ == "__main__":
    main()

How the Program Is Organized

Almost all of the code is inside the main() function. The last two lines call main() when you run the file. If you did the main.py lesson, you know this pattern. Inside main(), the program has four parts:

  1. Set the scores to zero.
  2. Get the player’s move. Keep asking until it is good, or quit.
  3. Say the player’s move, count to three, and say the computer’s move.
  4. Decide who won and add to the score. Then go back to step 2.

Importing sys

import random
import time
import sys

You know random and time. The sys module, short for “system,” has tools for working with Python itself. This program uses sys.exit(), which ends the program right away.

Setting Up the Score

def main():
    """Main game function"""
    # Scoring variables
    wins = 0
    losses = 0
    ties = 0

The first line in the body of main() is a docstring for the function. Like a file’s docstring, it describes what the function does.

The three variables hold the score. They are set to zero once, before the game loop starts, so they keep counting across rounds.

The Game Loop: while True

    while True:  # Main game loop.

A while loop runs as long as its condition is True. Here the condition is True, so it is always true. This loop would run forever. Programmers use while True: when there is no simple condition for stopping, and the program will leave the loop some other way. Here, that way is sys.exit(), when the player types Q.

If you ever start a program with an endless loop by accident, press Control+C in the command prompt to stop it.

Getting the Player’s Move

        player_move = ""

This is the “ask until the answer is good” loop you know from the coin game, with some clever additions.

Empty Strings Count as False

Look at if player_move:. There is no comparison here, just a variable. When Python uses a string as a condition, an empty string counts as False and any other string counts as True.

>>> bool("")
False
>>> bool("x")
True

bool() shows you whether a value counts as True or False.

The first time through the loop, player_move is the empty string, so the else block runs. It reads the score and the full instructions. If the player types something that is not R, P, S, or Q, the loop runs again. This time player_move holds what they typed, which is not empty, so the program says the shorter message, Type one of R, P, S, or Q.

This is good design for the ear. The player hears the full menu once per round, and a short correction if they make a mistake. They do not have to listen to the whole menu again.

Chaining a Method onto a Function Call

            player_move = input("> ").upper()

input() returns a string, and strings have an upper() method. So you can call upper() right on the result of input(), all in one line. Python calls input() first, then calls upper() on what it returned. Doing several calls in a row like this is called chaining.

The prompt is a greater-than sign and a space. It is short, which is nice once the player knows the game. Your screen reader will say “greater” before the player types.

Quitting with sys.exit()

If the player typed Q, the program says goodbye and calls sys.exit(). The program ends right there, from inside both loops.

elif Statements

elif is short for “else if.” It lets you check more than two possibilities. Python checks the if condition first. If it is False, Python checks the first elif. If that is False, it checks the next elif, and so on. As soon as one condition is True, Python runs that block and skips all the rest. At most one block runs.

Listen for the indentation. The if and both elif lines are at the same level. Each has two indented lines under it.

Each block also changes player_move from one letter to the full word, such as "ROCK". That way it can be compared with the computer’s move, which is also a full word.

Counting to Three

        time.sleep(0.5)
        print("1...")
        time.sleep(0.25)
        print("2...")
        time.sleep(0.25)
        print("3...")
        time.sleep(0.25)

These pauses build suspense, the way people count “rock, paper, scissors, shoot” out loud. The three dots after each number make many screen readers pause a little, too.

The Computer’s Move

        print(computer_move)

The computer picks at random, just like in random_item.py. The result is stored so it can be printed and then compared.

Deciding Who Won

        if player_move == computer_move:
            print("It's a tie!")
            ties = ties + 1
        elif True in [
            (player_move == "ROCK" and computer_move == "SCISSORS"),
            (player_move == "PAPER" and computer_move == "ROCK"),
            (player_move == "SCISSORS" and computer_move == "PAPER"),
        ]:
            print("You win!")
            wins = wins + 1
        else:
            print("You lose!")
            losses = losses + 1

First, if both moves are the same, it is a tie.

The and Operator

Each of the three lines in the list uses and. An and expression is True only if both sides are True.

>>> True and True
True
>>> True and False
False
>>> player_move = "ROCK"
>>> computer_move = "SCISSORS"
>>> player_move == "ROCK" and computer_move == "SCISSORS"
True

So (player_move == "ROCK" and computer_move == "SCISSORS") is True only when the player picked rock and the computer picked scissors. That is one way to win. The other two lines are the other two ways to win.

True in a List

The program puts the three win checks in a list. Python works out each one, so the list becomes something like [False, True, False]. Then True in [...] asks whether any of them is True. If any is, the player won.

This is a neat trick, but it is not the most common way to write it. Most Python programmers would use or to join the three checks:

        elif (
            (player_move == "ROCK" and computer_move == "SCISSORS")
            or (player_move == "PAPER" and computer_move == "ROCK")
            or (player_move == "SCISSORS" and computer_move == "PAPER")
        ):

Both work the same way. The list is split over several lines, one win per line, which is easier to read with a screen reader than one very long line.

Losing

If it is not a tie and the player did not win, the computer must have won. So the else block does not need to check anything.

Keeping Score

wins = wins + 1 adds one to wins. You could also write wins += 1. Both do the same thing.

After this, the loop goes back to the top, and the player hears the new score.

Designing for the Ear

This game does several things well for players who listen:

  • The full menu is read at the start of each round. A short message is read if the player makes a mistake.
  • The score is read before each round, so the player always knows where they stand.
  • Pauses and the “1, 2, 3” count give the player time to listen.
  • Moves are said in capital letters, which some screen readers say with more emphasis.

One thing could be better. The score says 1 Wins and 1 Losses, which sounds odd. You will fix that in an exercise.

Summary

You wrote a complete game of Rock, Paper, Scissors. You learned that:

  • while True: makes a loop that runs until something like sys.exit() stops it.
  • sys.exit() ends the program right away.
  • You can chain a method onto a function call, as in input("> ").upper().
  • An empty string counts as False in a condition.
  • elif checks another condition when the ones before it were False.
  • and is True only when both sides are True.
  • True in [...] checks whether any condition in a list is True.
