Saying Hello with a Variable

In the last lesson your program said hello to the whole world. In this lesson it will say hello to a person. To do that, you will store the person’s name in a variable and then put that variable inside a message with an f-string.

Variables and f-strings are in almost every program you will write from now on, so this short program is an important one.

Topics covered in this lesson

  • Docstrings
  • Comments
  • Variables
  • The assignment operator, =
  • f-strings

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

Sample Run

When you run the program, you hear:

Hellow Kathy!

The Source Code for Hello Variable

Make a new file, type in this program, and save it as hello_variable.py:

"""Example of  simple f string print"""
name = "Kathy"

# print a variable with a f string
print(f"Hellow {name}!")

Run it by typing python hello_variable.py at the command prompt.

The program has five lines. One of them is blank. Python skips blank lines, but they make a program easier to read by breaking it into parts, the same way paragraphs break up a story.

Docstrings

The first line is a string by itself:

"""Example of  simple f string print"""

It starts and ends with three double quotes. A string at the very top of a file is called a docstring. It describes what the file is for. Python does not print it or do anything with it when the program runs. It is a note for people who read the code, including you, weeks from now.

Three quotes in a row let a string go on for more than one line. Docstrings almost always use them, even when the note fits on one line.

Variables

The next line makes a variable:

name = "Kathy"

A variable is a name that holds a value. Think of it as a labeled box. The label on this box is name, and inside the box is the string "Kathy".

The equal sign is called the assignment operator. It does not mean “is equal to” the way it does in math. It means “put the value on the right into the variable on the left.” Read the line out loud as “name gets Kathy” or “set name to Kathy.”

Try it in the interactive shell:

>>> name = "Kathy"
>>> name
'Kathy'
>>> name = "Jordan"
>>> name
'Jordan'

When you type just a variable’s name in the shell, Python tells you what is in it. Notice that when you put a new value in the variable, the old value is gone. A variable holds one value at a time.

Naming Variables

You get to choose your variable names. Pick names that say what the variable holds. name is a good name for a person’s name. x would work too, but you would have to remember what x means.

Variable names can use letters, numbers, and the underscore, _. They cannot have spaces and cannot start with a number. If you need more than one word, join the words with underscores, as in first_name or player_score. Underscores are read clearly by screen readers, which is one reason Python programmers like them.

Variable names are case sensitive. name, Name, and NAME are three different variables.

Comments

The next line starts with a number sign, #:

# print a variable with a f string

This is a comment. Python ignores everything from the # to the end of the line. Comments are notes for people. Use them to explain why you did something, or to label a part of your program.

f-strings

The last line prints the greeting:

print(f"Hellow {name}!")

There is an f right before the opening quote. That f makes this an f-string, which is short for “formatted string.” In an f-string, anything inside curly braces, { and }, is not printed as is. Instead, Python looks it up and puts its value in that spot.

So f"Hellow {name}!" becomes Hellow Kathy! because name holds "Kathy".

Try it in the shell, and then try it without the f:

>>> name = "Kathy"
>>> print(f"Hello {name}!")
Hello Kathy!
>>> print("Hello {name}!")
Hello {name}!

Without the f, Python treats the braces as ordinary characters and prints them. Forgetting the f is a very common mistake. If you ever hear your screen reader say “left brace” in your program’s output, check for a missing f.

You can put more than one variable in an f-string:

>>> first = "Kathy"
>>> pet = "cat"
>>> print(f"{first} has a {pet}.")
Kathy has a cat.

The Typo, Again

Like the last program, this one prints Hellow instead of Hello. Now that you know how the line works, you know that Hellow is part of the string, not part of the variable. Fix it by changing the text inside the quotes.

Summary

This short program introduced ideas you will use constantly:

  • A docstring at the top of a file says what the program does.
  • A comment starts with # and is ignored by Python.
  • A variable is a name that holds a value.
  • The = sign puts a value into a variable.
  • An f-string starts with f and fills in anything inside curly braces with its value.
