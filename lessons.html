Python Game Lessons

These lessons teach Python by building games that are played by ear. Every game talks to the player in plain words that a screen reader can read, and many use sound. The lessons are written for people who are blind or have low vision, and for anyone who wants to learn to make games that everyone can play.

There are 38 lessons in nine parts. They are listed in the best order to take them. Each lesson builds on the ones before it, so start at lesson 1 and work down the list. Every lesson teaches one Python program, and every program is in the same folder as its lesson.

How to Use These Lessons

  • Each part is a heading, so you can jump from part to part with your screen reader's heading keys. The lessons in each part are a numbered list of links.
  • Each lesson has a short description and a level: Beginner, Intermediate, or Advanced.
  • In each lesson, type the program yourself, run it, and then do the exercises at the end. Typing the code is the best way to learn it.
  • Run each program from inside its own folder, so it can find its sound files.
  • Turn on indentation reporting and set punctuation to "all" in your screen reader while you work with code. Each lesson explains why.

What You Need

You need Python 3 and a code editor that works well with your screen reader. Some lessons also need extra modules. Install them from the command prompt when you get to the lesson that uses them:

  • pip install playsound for the lessons with sound, starting at lesson 4. If it gives errors, try pip install playsound==1.2.2.
  • pip install PySide6 for lesson 35.
  • pip install wxPython for lesson 36.
  • pip install pygame accessible_output2 for lesson 37.

Many of these programs have bugs. That is on purpose for learning, not an accident in the lessons. Several lessons have a section on finding and fixing bugs, because reading and fixing code is one of the most important skills a programmer can have.

Part 1: Your First Programs

Write and run your first programs, store values in variables, and let the computer pick at random. Add sound.

  1. Your First Program: Hello World Beginner. Make the computer say hello. Learn to save and run a program, use print(), and read error messages.
  2. Saying Hello with a Variable Beginner. Store a name in a variable and put it in a message with an f-string. Also covers comments and docstrings.
  3. Flipping a Coin Beginner. Import the random module, make your first list, and pick heads or tails at random.
  4. Adding Sound to the Coin Flip Beginner. Install a module with pip and play a sound file before the result.
  5. Rolling a Die Beginner. Pick a random number with random.randint(), and learn the difference between numbers and strings.
  6. Rolling a Die with Sound Beginner. Reuse what you know to add sound, and think about the order players hear things in.

Part 2: Loops and Decisions

Listen to the player, check their answers, make decisions, and repeat things. The part ends with Pig, your first big game.

  1. Guess the Coin Flip Beginner. Your first real game. Get input from the player, ask again until the answer is good with a while loop, and decide with if and else.
  2. Checking the Player's Choice Beginner. Check a menu choice with in, and learn a mistake that is very easy to miss by ear: a missing f.
  3. Rolling Many Dice Beginner. Repeat code with a for loop and range(), use constants, and build file paths with the os module.
  4. Printing a List of Choices Beginner. Read a list out loud two ways: by item, and by index with len().
  5. Picking a Random Rock, Paper, or Scissors Beginner. Build the computer's half of a game, and learn why you store a random result in a variable.
  6. Pig: A Dice Game for Many Players Beginner to Intermediate. A push-your-luck game for 2 to 10 players. Plan a program in plain English, use loops inside loops, take turns with %, use continue and break, pause with time.sleep(), and find a bug that stops player 1 from ever winning.

Part 3: Functions and a Complete Game

Learn the shape of a well-organized Python program, then use it to write a complete game.

  1. A Starting Point for Every Program Beginner. Define your own function with def, and learn what if __name__ == "__main__": means.
  2. Rock, Paper, Scissors Intermediate. A complete game with a score. Covers while True:, sys.exit(), elif, and, and designing menus that are quick to hear.

Part 4: Card Games

Build a deck of cards, then build Blackjack one tested piece at a time.

  1. Building and Shuffling a Deck of Cards Intermediate. Make 52 cards with nested loops and a list of lists. Copy and shuffle a list, and turn a card into words with join().
  2. Dealing Cards with Sound Intermediate. Deal with a random sound for each card, and track down an off-by-one error.
  3. Adding Up a Blackjack Hand Intermediate. Write a function that takes an argument and returns a value. Handle Aces, trace code by hand, and test your function with known answers.
  4. Showing the Blackjack Table Intermediate. Combine small functions, build a string in a loop, and make a hand of cards easier to hear.
  5. Blackjack Intermediate. Put the pieces together into a full game against the dealer. Learn why the order of your checks matters.

Part 5: Hangman

Plan a bigger game before you write it, and design it to be played entirely by ear.

  1. Designing and Writing an Accessible Hangman Intermediate. Plan with a flowchart in words, read words from a file, use many string and list methods, and organize a big program into small functions.

Part 6: Tic Tac Toe

Build Tic Tac Toe step by step, from storing the board to a computer opponent with three difficulty levels.

  1. Planning the Tic Tac Toe Board Intermediate. Design how a game stores its information, and explore it with python -i.
  2. Printing the Tic Tac Toe Board Intermediate. Print the board, compare how it sounds with a screen reader, and notice repeated code.
  3. A Function to Display the Board Intermediate. Turn repeated code into a function.
  4. Letting Players Mark a Square Intermediate. Functions that return True or False, slices, and list comprehensions that check every kind of bad input at once.
  5. A Whole Game of Tic Tac Toe Without Functions Intermediate. Check rows, columns, and diagonals with slices, and find the bugs caused by continue in nested loops.
  6. A Function to Check for a Winner Intermediate. Use return to fix those bugs, and test every way to win.
  7. An Easier Way to Check for a Winner Intermediate. Rewrite the check with tuples, chained comparisons, and sets, and re-run your tests to prove it still works.
  8. Tic Tac Toe with Functions Intermediate. Put the tested functions together into a complete two-player game.
  9. Tic Tac Toe Against the Computer Intermediate to Advanced. Menus, a computer player that tries to win and block, and a guided hunt for four real bugs.

Part 7: Classes and a Text Adventure

Make your own types with classes, and build a cave adventure game out of rooms, items, and a player.

  1. Classes: The Unit Blueprint Intermediate. Your first class. Learn about objects, __init__(), self, attributes, and methods.
  2. Inheritance: The Item Class Intermediate. Build one class on top of another with inheritance and super().
  3. The Player Class Intermediate. None, getters and setters, and objects that refer to other objects.
  4. The Room Class Intermediate to Advanced. Dictionaries, describing a room for the ear, tracing code to see what it assumes, and reading a linter report.
  5. The Cave of the Golden Box Advanced. A complete text adventure. Build a map, understand typed commands with a dictionary of functions, handle errors with try and except, and find bugs by playing.

Part 8: Games in a Window

Move from the command prompt to windows and buttons, and make them work well with screen readers.

  1. Tic Tac Toe in a Window with PySide6 Advanced. Event-driven programming, signals and slots, closures, message boxes, and accessible names for screen readers.
  2. Tic Tac Toe in a Window with wxPython Advanced. The same game with a second toolkit. Compare the two, and learn how native controls get their names for screen readers.

Part 9: Real-Time Audio Games

Make a fast action game that you play by listening, with sound that moves around your head.

  1. Rebound: An Audio Breakout Game Advanced. A game loop, delta time, collision detection, stereo panning, 3D sound, pitch that tells you height, and speech through your screen reader.
  2. Inside openal.py: Reading a Library You Did Not Write Advanced. Find your way around a 4,000-line file, call C code with ctypes, use properties, and learn how 3D sound works.
