Rebound: An Audio Breakout Game

Rebound is a real-time action game designed to be played by ear. A ball bounces around the screen, and you move a paddle left and right to keep it in play and knock out a wall of blocks at the top. You never need to see the screen. You hear where the ball is: its sound moves left and right as it travels across, and its pitch rises as it climbs toward the top. A beep tells you when there are blocks above your paddle, and your screen reader tells you how many are left.

Rebound was written by Blindgoofball from Nibble Nerds, at nibblenerds.com.

Every game so far has waited for the player to type something. Rebound does not wait. It runs sixty times a second, moving the ball, checking for collisions, and updating the sound, whether you press a key or not. In this lesson you will learn how real-time games work, and how to design sound so a player can track a moving object without seeing it.

This is an advanced lesson. It uses several modules you have to install, and ideas from math such as coordinates and velocity.

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

This program is indented with two spaces per level, not four. Python allows any number of spaces, as long as each block is consistent. If your screen reader reports indentation in spaces, you will hear 2, 4, 6, and so on. Most Python programs use four, which is what the style guide recommends.

Getting Ready

Rebound needs three things that do not come with Python:

  • pygame, a popular module for making games. Install it with pip install pygame. If that fails on a very new version of Python, try pip install pygame-ce, a community edition that works the same way and is imported with the same name.
  • accessible_output2, which sends speech to your screen reader. Install it with pip install accessible_output2.
  • OpenAL, a library for 3D sound. The rebound folder already has what you need: openal.py, which is a Python wrapper for OpenAL, and OpenAL32.dll, the OpenAL library for Windows. Both must stay in the same folder as rebound.py. The next lesson, on openal.py, explains how it works.

Run the game from the rebound folder with python rebound.py. As written, it works on Windows, because OpenAL32.dll is a Windows file.

How to Play

  • Press Space to launch the ball from your paddle.
  • Hold the Left and Right Arrow keys to move the paddle.
  • Listen to the ball. When it sounds to your left, move left. When it is to your right, move right. When it is centered between your ears, it is right above you. Its pitch gets higher as it rises and lower as it falls toward you.
  • When the ball touches a block, the block breaks with a crash sound.
  • A steady beep means there are blocks right above your paddle. Line up with the beep to aim at blocks.
  • Press B to hear how many blocks are left.
  • Press C to hear how many blocks are above your paddle.

Headphones make a big difference. They let you hear left and right clearly.

The Source Code for Rebound

Type this program and save it as rebound.py in the rebound folder:

"""
Rebound
A simple breakout style game
Written by Blindgoofball from Nibble Nerds
https://nibblenerds.com
"""
import openal
import accessible_output2.outputs.auto
from random import randint
import os
os.environ['PYGAME_HIDE_SUPPORT_PROMPT'] = "hide"
import pygame

o=accessible_output2.outputs.auto.Auto()
pygame.init()
pygame.mixer.init()

width=800
height=600

paddle_position=[width/2-20, height-40]
ball_position=[width/2, height-70]
ball_velocity=[0, 0]

listener=openal.Listener()
listener.distance_model=5
listener.position=(width/2, height-40, 0)

front_sound=pygame.mixer.Sound('sounds/beep.wav')
ball_sound=openal.LoadSound('sounds/ball.wav')
ball_source=openal.Player()
ball_source.add(ball_sound)
ball_source.position=(width/2, height-50, 0)
ball_source.loop=True
ball_source.rolloff=0.1
ball_source.reference_distance=0.1

paddle=pygame.rect.Rect(paddle_position[0], paddle_position[1], 40, 40)
ball=pygame.rect.Rect(0, 0, 10, 10)
ball.center=ball_position

blocks=[]
for i in range(width//40):
  for j in range((height-200)//40):
    blocks.append(pygame.rect.Rect(i*40, j*40, 40, 40))

def get_pitch(y):
  return 1.0+((height-y)/height)*(2.0)

def move_ball():
  ball_position[0]+=ball_velocity[0]*delta_time
  ball_position[1]-=ball_velocity[1]*delta_time
  ball.center=ball_position
  if ball.left < 0 or ball.right > width:
    bounce=pygame.mixer.Sound('sounds/bounce.wav')
    channel=pygame.mixer.find_channel()
    if ball.left < 0:
      channel.set_volume(1.0, 0.0)
    else:
      channel.set_volume(0.0, 1.0)
    channel.play(bounce)
    ball_velocity[0]*=-1
    ball_position[0]+=ball_velocity[0]*delta_time
  if ball.top < 0 or ball.bottom > height:
    ball_velocity[1]*=-1
    ball_position[1]-=ball_velocity[1]*delta_time
    pygame.mixer.Sound('sounds/bounce.wav').play()
  ball_source.position=(ball_position[0], ball_position[1], 0)
  ball_source.pitch=get_pitch(ball_position[1])

screen=pygame.display.set_mode((width, height))
pygame.display.set_caption('Rebound')
started=False
clock=pygame.time.Clock()
delta_time=0
ball_source.play()
while True:
  for event in pygame.event.get():
    if event.type == pygame.QUIT:
      pygame.quit()
      break
    elif event.type == pygame.KEYDOWN:
      if event.key == pygame.K_b:
        o.speak(f"{len(blocks)} blocks remaining.")
      elif event.key == pygame.K_c:
        o.speak(str(len(in_front)))
  keys=pygame.key.get_pressed()
  if keys[pygame.K_SPACE] and not started:
    ball_position=[paddle_position[0]+20, paddle_position[1]-30]
    ball_velocity=[0, 150]
  if keys[pygame.K_LEFT] and paddle.left >= 5:
    paddle_position[0]-=5
    listener.position=(paddle_position[0], paddle_position[1], 0)
  if keys[pygame.K_RIGHT] and paddle.right <= width-5:
    paddle_position[0]+=5
    listener.position=(paddle_position[0], paddle_position[1], 0)
  move_ball()
  paddle.center=paddle_position
  screen.fill((0, 0, 0))
  for block in blocks:
    pygame.draw.rect(screen, (255, 255, 255), block, 1)
  pygame.draw.rect(screen, (0, 255, 0), paddle)
  pygame.draw.rect(screen, (0, 0, 255), ball)
  pygame.display.update()
  if pygame.Rect.colliderect(ball, paddle) and ball_position[0] <= paddle_position[0]:
    ball_velocity[1]*=-1
    ball_velocity[0]=randint(-75, 0)
    pygame.mixer.Sound('sounds/deflect.wav').play()
  elif pygame.Rect.colliderect(ball, paddle) and ball_position[0] > paddle_position[0]:
    ball_velocity[1]*=-1
    ball_velocity[0]=randint(0, 75)
    pygame.mixer.Sound('sounds/deflect.wav').play()
  for block in range(len(blocks)):
    if pygame.Rect.colliderect(ball, blocks[block]):
      del blocks[block]
      pygame.mixer.Sound('sounds/collide.wav').play()
      break
  in_front=[block for block in blocks if block.left >= paddle.left and block.right <= paddle.right]
  if in_front:
    if not front_sound.get_num_channels():
      front_sound.play(-1)
  else:
    front_sound.stop()
  delta_time=clock.tick(60)/1000
ball_source.delete()
ball_sound.delete()
listener.delete()

How the Program Is Organized

The program is written from top to bottom with only two functions of its own:

  1. Import the modules and set up speech, pygame, and the screen size.
  2. Set up the paddle, the ball, the OpenAL listener, and the ball’s sound.
  3. Build the wall of blocks.
  4. Define get_pitch() and move_ball().
  5. Open the window and run the game loop forever.

Importing and Setting Up

import openal
import accessible_output2.outputs.auto
from random import randint
import os
os.environ['PYGAME_HIDE_SUPPORT_PROMPT'] = "hide"
import pygame

import accessible_output2.outputs.auto imports a module that is three levels deep inside a package. The periods separate the levels, like folders.

from random import randint brings in just the randint function, so the program can write randint() instead of random.randint().

Environment Variables

os.environ is a dictionary of environment variables, settings that the operating system gives to every program. pygame normally prints a hello message when it is imported. Setting PYGAME_HIDE_SUPPORT_PROMPT before the import turns that off. That matters for screen reader users, who would otherwise hear it every time the game starts. This is why import pygame comes after this line, instead of at the top with the others.

Speech and Sound

o=accessible_output2.outputs.auto.Auto()
pygame.init()
pygame.mixer.init()

Auto() makes an object that finds whatever screen reader is running, such as NVDA or JAWS, and speaks through it. If none is running, it uses the computer’s built-in speech. Later, o.speak("text") says the text. This is better than print() for a game, because a game window is not a text console, and the screen reader would not read printed text there.

The name o is very short. A name like speech would be easier to understand when you hear it.

pygame.init() starts all of pygame’s parts. pygame.mixer.init() starts its sound system.

Coordinates

width=800
height=600

paddle_position=[width/2-20, height-40]
ball_position=[width/2, height-70]
ball_velocity=[0, 0]

The game takes place on a screen 800 pixels wide and 600 tall. A position is written as two numbers, x and y. x is how far from the left edge. y is how far from the top edge. In screen coordinates, y gets bigger as you go down, which is the opposite of what you may know from math class.

So the paddle starts near the middle, at x of 380, and near the bottom, at y of 560. The ball starts just above it.

Positions are stored as lists of two numbers, so they can be changed: ball_position[0] is x and ball_position[1] is y.

Velocity

ball_velocity is how fast the ball moves, and in which direction, in pixels per second. The first number is the speed left or right, and the second is the speed up or down. It starts at zero, because the ball does not move until the player presses Space.

The Listener and the Ball’s Sound

This is the part that makes Rebound playable by ear. OpenAL places sounds in a 3D space and figures out how they would sound to a listener standing somewhere in that space. A sound to the listener’s left plays more in the left ear. A sound far away is quieter.

listener=openal.Listener()
listener.distance_model=5
listener.position=(width/2, height-40, 0)

The listener is your ears. It is placed at the paddle. A position in OpenAL has three numbers, x, y, and z. This game is flat, so z is always 0. The distance_model setting tells OpenAL how sounds get quieter with distance. Model 5 is the exponential model, which you can learn about in the openal.py lesson.

front_sound=pygame.mixer.Sound('sounds/beep.wav')
ball_sound=openal.LoadSound('sounds/ball.wav')
ball_source=openal.Player()
ball_source.add(ball_sound)
ball_source.position=(width/2, height-50, 0)
ball_source.loop=True
ball_source.rolloff=0.1
ball_source.reference_distance=0.1

The beep that plays when blocks are above the paddle is an ordinary pygame sound. The ball’s sound uses OpenAL:

  • LoadSound() loads the sound file into memory.
  • Player() makes a source, a point in space that makes sound. The sound is added to it.
  • The source is placed where the ball is.
  • loop=True makes the sound repeat forever, so the ball always makes a sound you can follow.
  • rolloff and reference_distance control how fast the sound gets quieter as it moves away.

Notice that lines like ball_source.loop=True look like they just set an attribute, but they actually change how OpenAL plays the sound. That is done with properties, which are explained in the openal.py lesson.

Rectangles

paddle=pygame.rect.Rect(paddle_position[0], paddle_position[1], 40, 40)
ball=pygame.rect.Rect(0, 0, 10, 10)
ball.center=ball_position

pygame uses Rect objects, short for rectangles, for things on the screen. A Rect knows its position and size, and has handy attributes like left, right, top, bottom, and center. The paddle is a 40 by 40 square, and the ball is a 10 by 10 square. Setting ball.center moves the ball so its center is at that position.

Rectangles make it easy to check whether two things are touching, which you will see below.

Building the Wall

blocks=[]
for i in range(width//40):
  for j in range((height-200)//40):
    blocks.append(pygame.rect.Rect(i*40, j*40, 40, 40))

// is floor division. It divides and throws away any remainder, giving a whole number. 800 // 40 is 20, and (600 - 200) // 40 is 10.

So the nested loops make 20 columns and 10 rows of 40 by 40 blocks, which is 200 blocks, filling the top 400 pixels of the screen. Each block’s position is its column times 40 and its row times 40.

Hearing Height with Pitch

def get_pitch(y):
  return 1.0+((height-y)/height)*(2.0)

Left and right are easy to hear with stereo sound. Up and down are much harder. So Rebound uses pitch to tell you how high the ball is.

When the ball is at the bottom, y is 600, so height - y is 0, and the pitch is 1.0, which is normal. When the ball is at the top, y is 0, so (height - y) / height is 1, and the pitch is 3.0, much higher. In between, the pitch slides smoothly. A high, squeaky ball is far away at the top. A low ball is coming down toward you.

Turning a number you cannot hear, like height, into one you can, like pitch, is called sonification. It is one of the most useful tools for making games and data accessible.

Moving the Ball

def move_ball():
  ball_position[0]+=ball_velocity[0]*delta_time
  ball_position[1]-=ball_velocity[1]*delta_time
  ball.center=ball_position

Delta Time

Each time through the game loop is called a frame. delta_time is how many seconds passed since the last frame, usually about one sixtieth of a second.

Velocity is in pixels per second. Multiplying by the seconds that passed gives how many pixels to move this frame. This keeps the ball moving at the same speed on a fast computer and a slow one. If the game just moved the ball 3 pixels every frame, it would move twice as fast on a computer that runs twice as many frames.

Notice the minus sign for y. Since y gets bigger going down, the program subtracts so that a positive y velocity moves the ball up.

Bouncing off the Side Walls

  if ball.left < 0 or ball.right > width:
    bounce=pygame.mixer.Sound('sounds/bounce.wav')
    channel=pygame.mixer.find_channel()
    if ball.left < 0:
      channel.set_volume(1.0, 0.0)
    else:
      channel.set_volume(0.0, 1.0)
    channel.play(bounce)
    ball_velocity[0]*=-1
    ball_position[0]+=ball_velocity[0]*delta_time

If the ball has gone past the left or right edge, it bounces. Multiplying the x velocity by -1 flips its direction. Then the ball is moved one step in the new direction so it is back inside the screen.

The bounce sound is panned. pygame plays sounds on channels, and a channel’s set_volume() can take two numbers: the left volume and the right volume. A bounce off the left wall plays only in the left ear, and a bounce off the right wall plays only in the right ear. That tells the player exactly where the ball is at that moment.

Bouncing off the Top and Bottom

  if ball.top < 0 or ball.bottom > height:
    ball_velocity[1]*=-1
    ball_position[1]-=ball_velocity[1]*delta_time
    pygame.mixer.Sound('sounds/bounce.wav').play()

The same idea, for up and down. This bounce sound plays in both ears.

Moving the Sound with the Ball

  ball_source.position=(ball_position[0], ball_position[1], 0)
  ball_source.pitch=get_pitch(ball_position[1])

Every frame, the ball’s OpenAL source moves to the ball’s new position, and its pitch is set from its height. This is what makes the ball’s sound travel around your head.

The Game Loop

screen=pygame.display.set_mode((width, height))
pygame.display.set_caption('Rebound')
started=False
clock=pygame.time.Clock()
delta_time=0
ball_source.play()
while True:

set_mode() opens the game window, and set_caption() sets its title, which your screen reader reads when the window gets focus. The Clock measures time between frames. Then the ball’s looping sound starts, and the game loop begins.

The loop does the same things every frame, in this order:

  1. Handle events, like key presses.
  2. Move the paddle if an arrow key is held.
  3. Move the ball.
  4. Draw everything.
  5. Check for collisions with the paddle and the blocks.
  6. Update the beep for blocks above the paddle.
  7. Wait until it is time for the next frame.

Events

  for event in pygame.event.get():
    if event.type == pygame.QUIT:
      pygame.quit()
      break
    elif event.type == pygame.KEYDOWN:
      if event.key == pygame.K_b:
        o.speak(f"{len(blocks)} blocks remaining.")
      elif event.key == pygame.K_c:
        o.speak(str(len(in_front)))

pygame.event.get() returns a list of everything that has happened since the last frame. A KEYDOWN event happens once when a key is first pressed. The B and C keys speak information through the screen reader. Commands that tell the player about the game, on demand, are very important in an audio game. The player cannot glance at a score display.

Held Keys

  keys=pygame.key.get_pressed()
  if keys[pygame.K_SPACE] and not started:
    ball_position=[paddle_position[0]+20, paddle_position[1]-30]
    ball_velocity=[0, 150]
  if keys[pygame.K_LEFT] and paddle.left >= 5:
    paddle_position[0]-=5
    listener.position=(paddle_position[0], paddle_position[1], 0)
  if keys[pygame.K_RIGHT] and paddle.right <= width-5:
    paddle_position[0]+=5
    listener.position=(paddle_position[0], paddle_position[1], 0)

Events are good for things that happen once. For movement, the game needs to know which keys are being held down right now. get_pressed() returns that, one entry per key.

Space puts the ball just above the paddle and sends it straight up at 150 pixels per second.

The arrow keys move the paddle 5 pixels per frame, as long as it is not at the edge. Each time the paddle moves, the listener moves with it. Your ears are always at the paddle, so the ball’s sound is always heard from where you are. That is the key to the whole design.

The paddle moves a fixed 5 pixels per frame, not using delta_time, so the paddle would move at different speeds on computers with different frame rates. The clock keeps the game near 60 frames per second, so this is usually fine.

Drawing

  move_ball()
  paddle.center=paddle_position
  screen.fill((0, 0, 0))
  for block in blocks:
    pygame.draw.rect(screen, (255, 255, 255), block, 1)
  pygame.draw.rect(screen, (0, 255, 0), paddle)
  pygame.draw.rect(screen, (0, 0, 255), ball)
  pygame.display.update()

The game also draws itself, for sighted players and players with some vision. Colors are tuples of red, green, and blue, each from 0 to 255. The screen is filled with black, the blocks are drawn as white outlines, the paddle is green, and the ball is blue. display.update() shows the finished frame.

A dark blue ball on a black background is hard to see for many people with low vision. A bright color like yellow or white would stand out much more.

Hitting the Paddle

  if pygame.Rect.colliderect(ball, paddle) and ball_position[0] <= paddle_position[0]:
    ball_velocity[1]*=-1
    ball_velocity[0]=randint(-75, 0)
    pygame.mixer.Sound('sounds/deflect.wav').play()
  elif pygame.Rect.colliderect(ball, paddle) and ball_position[0] > paddle_position[0]:
    ball_velocity[1]*=-1
    ball_velocity[0]=randint(0, 75)
    pygame.mixer.Sound('sounds/deflect.wav').play()

colliderect() returns True if two rectangles overlap. This is collision detection, and it is how almost every 2D game knows when things touch.

If the ball hits the left half of the paddle, it bounces back up and to the left, at a random angle. If it hits the right half, it goes up and to the right. This gives the player some control over where the ball goes, which they can use to aim at the beeping blocks.

Breaking Blocks

  for block in range(len(blocks)):
    if pygame.Rect.colliderect(ball, blocks[block]):
      del blocks[block]
      pygame.mixer.Sound('sounds/collide.wav').play()
      break

The loop checks each block. When the ball touches one, the block is deleted from the list, a crash plays, and break stops the loop. The break is important. Deleting from a list while looping over its indexes would skip items or go past the end, as you saw in the Room lesson.

The ball does not bounce off blocks. It plows through, breaking one block per frame, until it reaches the top wall.

Blocks Above the Paddle

  in_front=[block for block in blocks if block.left >= paddle.left and block.right <= paddle.right]
  if in_front:
    if not front_sound.get_num_channels():
      front_sound.play(-1)
  else:
    front_sound.stop()

The list comprehension finds every block that is directly above the paddle. If there are any, the beep plays. play(-1) loops it forever, and get_num_channels() checks whether it is already playing, so it is not started again every frame. If there are no blocks above, the beep stops.

This is a clever audio cue. A sighted player can see where the blocks are. A blind player hears the beep and knows that a ball sent straight up from here will hit something.

Waiting for the Next Frame

  delta_time=clock.tick(60)/1000

clock.tick(60) waits just long enough to keep the game at 60 frames per second. It returns how many milliseconds passed since the last call. Dividing by 1000 turns that into seconds, which is what delta_time needs.

Finding the Bugs

Rebound is fun to play, but like all games in progress, it has some bugs.

Closing the Window Causes an Error

When you close the window, pygame sends a QUIT event. The program calls pygame.quit() and then break. But break only leaves the for event loop, not the while True loop. The game loop keeps going and calls pygame.key.get_pressed(), but pygame has been shut down, so the program stops with an error.

Because the while True loop never ends normally, the last three lines, which free the OpenAL sounds, never run either.

One fix is a flag variable. Set running = True before the loop, change the loop to while running:, and set running = False when the QUIT event arrives. Then call pygame.quit() after the loop, along with the OpenAL cleanup.

Space Works at Any Time

The variable started is set to False and checked when Space is pressed, but it is never set to True. So pressing Space at any time puts the ball back on the paddle. That is a handy cheat, but probably not intended.

You Cannot Lose

When the ball reaches the bottom of the screen, it just bounces, as if there were a wall there. There is no way to miss. Adding lives, and a sound and a spoken message when the ball is missed, would make it a real challenge.

You Cannot Win

When the last block breaks, nothing happens. The game should say that you won.

Loading Sounds Over and Over

Every bounce, deflect, and collide loads its .wav file from the disk again, with pygame.mixer.Sound(...). That works, but it is slow. It is better to load each sound once, before the game loop, and store it in a variable, the way front_sound is.

Summary

You studied a real-time audio game. You learned that:

  • A game loop runs many times a second, whether or not the player does anything. Each time through is a frame.
  • Multiplying velocity by delta time keeps speed the same on any computer.
  • In screen coordinates, y gets bigger going down.
  • Flipping the sign of a velocity makes something bounce.
  • pygame rectangles make collision detection easy with colliderect().
  • Events are for things that happen once. get_pressed() is for held keys.
  • Stereo panning tells the player left and right. 3D audio with OpenAL can move a sound smoothly around the listener.
  • Pitch can stand for height, so the player can hear where the ball is.
  • An audio cue, like the beep, can replace something a sighted player would see.
  • accessible_output2 speaks through the player’s screen reader.
  • break only leaves the innermost loop.
