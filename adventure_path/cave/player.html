The Player Class

The player is the hero of the cave game. Like an item, the player has names, a title, and a description, so the Player class inherits from Unit. But a player also has things an item does not: health that goes down as they walk, a location in the cave, and a bag of items they are carrying. A player can also do things, such as move from room to room and pick things up.

In this lesson you will see how an object keeps track of changing information, and how one object can hold a reference to another.

Topics covered in this lesson

  • A child class with several new attributes
  • None
  • Methods that change an object’s attributes
  • Getters and setters
  • Objects that refer to other objects
  • Making a list only when it is needed
  • Joining two strings that sit next to each other

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

The Source Code for Player

Type this program and save it as player.py in the cave folder:

"""Player information class""" "cave.lnt"

from unit import Unit


class Player(Unit):
    """

    This class defines the basic Player.
    """

    def __init__(self, n, t, d):
        """Constructor"""

        super().__init__(n, t, d)

        self.health = 8

        self.location = None

        self.items = None

    def can_move(self, direction):
        """Checks if player can move."""
        return self.location.has_exit(direction)

    def set_location(self, room):
        """Sets the room player is in"""
        self.location = room

    def get_location(self):
        """Get player current location"""
        return self.location

    def get_health(self):
        """REturn current health"""

        return self.health

    def lose_health(self):
        """decrease health by one"""

        self.health -= 1

        return self.health

    def move(self, direction):
        """move player in a direction"""
        self.location = self.location.exits[direction]

        print("You move ", direction)

        print(self.location.get_room_string())

    def add_item(self, item):
        """Adds an item to players inventory"""
        if not self.items:
            self.items = []
        if item:
            self.items.append(item)

A Strange First Line

"""Player information class""" "cave.lnt"

This line has two strings next to each other with only a space between them. Python has a rule that two string literals side by side are joined into one. So the docstring is really "Player information classcave.lnt".

>>> "Hello " "world"
'Hello world'

The "cave.lnt" part was almost certainly added by accident. A .lnt file is the output from a linter, a tool that reads code and reports problems. There is a file like that, room.lnt, in this folder. You can delete "cave.lnt" from the docstring.

Setting Up a Player

class Player(Unit):
    def __init__(self, n, t, d):
        """Constructor"""

        super().__init__(n, t, d)

        self.health = 8

        self.location = None

        self.items = None

Like Item, Player inherits from Unit and calls super().__init__() first, so the parent sets up the names, title, and description. Then it adds three attributes of its own:

  • health starts at 8. The player loses one each time they move.
  • location will hold the room the player is in.
  • items will hold the things the player is carrying.

The file has a blank line between almost every line of code. Python ignores blank lines, so it does no harm. But with a screen reader, every blank line is one more press of the down arrow. Most Python code uses blank lines only to separate groups of related lines.

None

location and items start as None. None is a special value in Python that means “nothing” or “no value yet.” It is not zero, and it is not an empty string. It is its own thing.

>>> x = None
>>> x is None
True
>>> print(x)
None

When a player is first made, they are not in any room yet, so location is None. The game puts them in a room right after making them.

None counts as False in a condition, like 0 and empty strings and empty lists do.

Setters and Getters

    def set_location(self, room):
        """Sets the room player is in"""
        self.location = room

    def get_location(self):
        """Get player current location"""
        return self.location

    def get_health(self):
        """REturn current health"""

        return self.health

set_location() is a setter. It changes an attribute. get_location() and get_health() are getters. They return an attribute. You met getters in the Item lesson.

Objects That Refer to Other Objects

When the game calls player.set_location(rooms[0]), the player’s location attribute holds a Room object. It does not hold a copy of the room. It holds the room itself. The player and the cave’s list of rooms both refer to the very same object.

This is how objects are connected to each other in a program. Through self.location, the player can reach their room and use its methods.

Can the Player Move?

    def can_move(self, direction):
        """Checks if player can move."""
        return self.location.has_exit(direction)

The player does not know which ways out a room has. The room knows. So the player asks its room, by calling the room’s has_exit() method. The direction is a string such as "north".

Read self.location.has_exit(direction) from left to right: this player, its location, which is a room, and that room’s has_exit() method. Long chains of periods like this are common when objects refer to other objects.

has_exit() returns the room in that direction, or None if there is no exit. A room counts as True and None counts as False, so the result works as a yes or no answer.

Losing Health

    def lose_health(self):
        """decrease health by one"""

        self.health -= 1

        return self.health

This method changes the player’s own health. Because health is an attribute, the change stays with the player after the method ends. It also returns the new health, in case the caller wants to know.

Moving

    def move(self, direction):
        """move player in a direction"""
        self.location = self.location.exits[direction]

        print("You move ", direction)

        print(self.location.get_room_string())

Each room has an attribute called exits, which is a dictionary that matches directions to rooms. You will learn about dictionaries in the Room lesson. self.location.exits[direction] looks up the room in that direction. The player’s location is changed to that new room.

Then the player hears where they went and a description of the new room.

print("You move ", direction) gives print() two arguments. print() puts a space between its arguments, and the first string already ends with a space, so the result has two spaces: You move north. You probably cannot hear it, but an f-string such as print(f"You move {direction}.") avoids it and adds a period, which makes the screen reader pause.

This method does not check whether there is an exit. It expects the caller to call can_move() first. If it did not, and there was no exit, the player’s location would become None, and the next line would cause an error.

Picking Things Up

    def add_item(self, item):
        """Adds an item to players inventory"""
        if not self.items:
            self.items = []
        if item:
            self.items.append(item)

The list of items the player carries is often called their inventory.

self.items starts as None. The first time the player picks something up, not self.items is True, so the method makes an empty list. After that, the list already exists, and the method just adds to it.

The second if makes sure there really is an item before adding it, so that None is never added to the list.

Making the list only when it is first needed works, but it means every piece of code that uses self.items has to remember it might be None. It is simpler to start with an empty list in __init__(): self.items = []. An empty list counts as False too, so the game’s checks would still work.

Trying Player in the Shell

A player needs a room, so this test uses the Room class too. In the cave folder, run python -i player.py, then:

>>> from room import Room
>>> hall = Room("hall", "Great Hall", "A huge stone hall.")
>>> yard = Room("yard", "Courtyard", "A grassy courtyard.")
>>> hall.set_direction("north", yard)
>>> yard.set_direction("south", hall)
>>> hero = Player(["Sam"], "a brave hero", "A brave hero with a lamp.")
>>> hero.set_location(hall)
>>> hero.can_move("north")
<room.Room object at 0x000001F2A3B4C5D0>
>>> hero.can_move("west")
>>> hero.move("north")

can_move("north") returns the courtyard room. The shell shows an object as its class name and a memory address, a long number that will be different on your computer. can_move("west") returns None, and the shell shows nothing for None. Then move("north") prints the courtyard’s description.

>>> hero.lose_health()
7
>>> hero.get_location().title
'Courtyard'

Summary

You studied the Player class. You learned that:

  • None means “no value yet,” and counts as False.
  • Setters change attributes and getters return them.
  • An attribute can hold another object, which connects the two objects.
  • One object can ask another for information by calling its methods.
  • A method that changes an attribute, like lose_health(), changes the object for good.
  • Two strings side by side are joined into one string.
  • Starting a list as [] is simpler than starting it as None.
