Classes: The Unit Blueprint

The cave adventure game is made of things: rooms you walk through, an item you can pick up, and a player who moves around. Each of these things has a name, a short title, and a longer description. In this lesson you will write a class called Unit that holds those three pieces of information and can answer one question: “Is this your name?”

Unit is small, but it is the foundation of the whole game. The Room, Item, and Player classes in the next lessons are all built on top of it. This lesson is your introduction to classes and objects, one of the most important ideas in Python.

Topics covered in this lesson

  • What classes and objects are
  • Defining a class with class
  • The __init__() method
  • self and attributes
  • Methods
  • Making objects and calling their methods
  • Splitting a program into several files

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

The Adventure Game Files

The cave game is split across five files, all in the cave folder:

  • unit.py has the Unit class, the base for everything else.
  • item.py has the Item class, for things you can pick up.
  • player.py has the Player class.
  • room.py has the Room class.
  • cave.py builds the cave and runs the game.

Splitting a program into files keeps each file short and focused. With a screen reader, a short file is much easier to move around in than one very long one. Each class gets its own file, and cave.py imports them.

The Source Code for Unit

Type this program and save it as unit.py in a folder named cave:

"""Base class for player, room, and item"""


class Unit:
    """
    This class defines the basic Unit.
    """

    def __init__(self, name, title, desc):
        """Constructor"""
        self.names = name
        self.title = title
        self.description = desc

    def is_name(self, name):
        """tests if this is the units name"""
        if name in self.names:
            return True
        return False

Running python unit.py does nothing you can hear. The file only defines a class. It does not make any objects or print anything. To try it out, you will use the interactive shell.

What Is a Class?

You have used many kinds of values: strings, numbers, lists. Each kind is a type, and each type has its own methods. Strings have upper(). Lists have append(). A class lets you make your own type.

A class is like a blueprint, or a form with blanks to fill in. The Unit class says: “Every unit has a list of names, a title, and a description, and it can tell you whether a word is one of its names.” The class itself is not a unit. It is the plan for making units.

An object is one thing made from the class. A unit for the gold box and a unit for a lamp would be two different objects made from the same class. Each has its own names, title, and description. An object is also called an instance of its class.

Defining a Class

class Unit:
    """
    This class defines the basic Unit.
    """

The class keyword starts a class definition. After it comes the name, Unit, and a colon. Class names start with a capital letter and use no underscores, like Unit or TreasureChest. This style helps you tell a class from a function or variable when you hear the name.

Everything indented under the class line belongs to the class. The first thing is a docstring that describes it.

The init() Method

    def __init__(self, name, title, desc):
        """Constructor"""
        self.names = name
        self.title = title
        self.description = desc

A function defined inside a class is called a method. This one has a special name: __init__, with two underscores before and after. Listen carefully for them. Your screen reader may say “underline underline init underline underline.” Programmers say “dunder init.”

Python calls __init__() automatically every time a new object is made. Its job is to set the new object up. That is why the docstring calls it the constructor.

self

The first parameter of every method is self. It is the object the method is working on. When Python makes a new unit and calls __init__(), self is that brand new unit.

You never pass self yourself. Python fills it in. So even though __init__() has four parameters, you make a unit with three arguments: the names, the title, and the description.

Attributes

        self.names = name

A variable that starts with self. is an attribute. It is stored inside the object, and it stays there as long as the object exists. Each unit has its own names, title, and description.

Compare that with an ordinary variable inside a function, which disappears when the function ends. The parameter name is gone when __init__() finishes, but self.names stays with the object.

Notice that the parameter is called name, but the attribute is called names, plural. The game passes a list of names, because the player might call the same thing several ways. A gold box might answer to “gold box,” “box,” or “gold.” So the attribute’s plural name is the more accurate one.

The is_name() Method

    def is_name(self, name):
        """tests if this is the units name"""
        if name in self.names:
            return True
        return False

This method answers one question: is the word the player typed one of this unit’s names? It uses in to check the list, and returns True or False.

You could write the same method in one line, because name in self.names is already True or False:

    def is_name(self, name):
        """tests if this is the units name"""
        return name in self.names

Both versions work the same way.

Trying Unit in the Shell

Open a command prompt in the cave folder and type:

python -i unit.py

The -i runs the file and then leaves you in the shell, with the Unit class ready to use. Now make a unit:

>>> lamp = Unit(["lamp", "brass lamp"], "a brass lamp", "An old brass lamp.")

This calls the class like a function. Python makes a new, empty Unit object, calls __init__() with self set to that object and your three arguments, and then puts the finished object in lamp.

Now look at its attributes. Use the object’s name, a period, and the attribute name:

>>> lamp.title
'a brass lamp'
>>> lamp.names
['lamp', 'brass lamp']
>>> lamp.description
'An old brass lamp.'

And call its method:

>>> lamp.is_name("lamp")
True
>>> lamp.is_name("brass lamp")
True
>>> lamp.is_name("box")
False

Make a second unit, and you will hear that it has its own attributes:

>>> box = Unit(["box"], "a wooden box", "A small wooden box.")
>>> box.title
'a wooden box'
>>> lamp.title
'a brass lamp'

Uppercase and Lowercase

Try this:

>>> lamp.is_name("Lamp")
False

in compares strings exactly, so a capital L does not match. In a game, players type in all kinds of ways. You will see this cause a real problem in the cave game, and an exercise asks you to fix it here, where it belongs.

Summary

You wrote your first class. You learned that:

  • A class is a blueprint for making objects. An object is one thing made from it.
  • class Name: starts a class. Class names start with a capital letter.
  • A function inside a class is called a method.
  • __init__() runs automatically when an object is made, to set it up.
  • self is the object a method is working on. Python passes it for you.
  • Attributes, like self.title, are stored in the object.
  • You make an object by calling the class: Unit(names, title, description).
  • You use an object’s attributes and methods with a period: lamp.title, lamp.is_name("lamp").

Exercises

  1. Rewrite is_name() to use one return line.
  2. Make is_name() ignore uppercase and lowercase. Hint: compare name.lower() with each name in the list made lowercase. A list comprehension can make the lowercase list.
  3. Add a method called describe() that returns the title and the description together in one string, such as a brass lamp: An old brass lamp.
  4. Rename the __init__() parameter name to names, so the parameter and the attribute match. Make sure you change every place it is used.
  5. In the shell, make three units of your own and call is_name() on each.
