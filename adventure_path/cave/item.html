Inheritance: The Item Class

In the last lesson you wrote the Unit class, which holds names, a title, and a description. An item in the cave game, such as the little gold box, needs all of that, plus one more thing: a cost, or value.

You could copy all of Unit into a new class and add the cost. But there is a better way. In this lesson you will make Item inherit from Unit. An item automatically gets everything a unit has, and you only write the parts that are new.

Topics covered in this lesson

  • Importing a class from another file
  • Inheritance: making a class from another class
  • Calling the parent’s __init__() with super()
  • Adding new attributes and methods
  • Getter methods

A Note on Reading Code with a Screen Reader

Python uses indentation, the spaces at the start of a line, to show which lines belong together. A line that ends with a colon, such as while True: or def main():, starts a block. Every line in that block is indented four more spaces than the line with the colon.

Before you start, turn on indentation reporting in your screen reader or code editor so you hear how far each line is indented. In NVDA this setting is called “Line indentation reporting” and is under Document Formatting. JAWS and most code editors have a similar setting. Many blind programmers like to hear indentation as tones, but spoken numbers work too.

It also helps to set your screen reader to read all punctuation while you are working with code. Punctuation matters in Python. A missing colon, quote, or parenthesis is one of the most common errors.

In this lesson, code you type into a file is shown in code blocks. Code you type into the interactive shell starts with three greater-than signs, >>>. That is the shell’s prompt. Do not type the prompt. Type only what comes after it. The lines with no prompt are what Python prints back.

The Source Code for Item

Type this program and save it as item.py in the cave folder, next to unit.py:

"""Item class for Cave game"""
from unit import Unit


class Item(Unit):
    """
    This class defines the basic item.
    """

    def __init__(self, n, t, d, c):
        """Constructor"""
        super().__init__(n, t, d)
        self.cost = c

    def get_title(self):
        """Return the title for this item"""
        return self.title

Like unit.py, this file only defines a class. Running it does nothing you can hear.

Importing from Your Own File

from unit import Unit

You have imported modules that come with Python, like random, and modules you installed, like playsound. You can also import from your own files. Every .py file is a module. Its name is the file name without .py.

This line says: from the module unit, which is the file unit.py, bring in the name Unit. Python looks for unit.py in the same folder as the program you are running. That is why both files must be in the cave folder.

Inheritance

class Item(Unit):

The name in parentheses after the class name is the class to inherit from. This line says that Item is a kind of Unit. Unit is called the parent class, base class, or superclass. Item is the child class, or subclass.

An Item object has everything a Unit has. It has names, title, and description attributes, and it has the is_name() method, even though none of them are written in item.py. They come from Unit.

A good way to check whether inheritance makes sense is to say “is a.” An item is a unit. A room is a unit. A player is a unit. All three share the same basic parts, which is why all three inherit from Unit.

The Item Constructor

    def __init__(self, n, t, d, c):
        """Constructor"""
        super().__init__(n, t, d)
        self.cost = c

An item’s constructor takes four values: names, title, description, and cost. The parameters are named with single letters, n, t, d, and c. That keeps the line short, but it is hard to know what they mean when you hear them. Names like names, title, desc, and cost would be clearer, especially by ear.

super()

super().__init__(n, t, d) calls the __init__() method of the parent class, Unit. That sets up the names, title, and description, exactly as Unit always does. super() means “my parent class.”

Then the next line adds the one thing that is new for items: self.cost.

This is the pattern for every child class. First, let the parent set up its part. Then, set up your own part. If you forgot the super() line, the item would have a cost but no names, title, or description, and calling is_name() would cause an error.

The get_title() Method

    def get_title(self):
        """Return the title for this item"""
        return self.title

This method just returns the item’s title. A method whose only job is to return an attribute is called a getter.

Code outside the class could read item.title directly, so why have a getter? Some programmers like getters because they make it possible to change how the title is stored later without changing every place that uses it. In Python, reading the attribute directly is also common and perfectly fine.

Notice that self.title is used here, but it was not set in Item. It was set in Unit.__init__() through the super() call. A child class can use all of its parent’s attributes.

Trying Item in the Shell

In the cave folder, run:

python -i item.py

Now make an item:

>>> coin = Item(["coin", "gold coin"], "a gold coin", "A shiny gold coin.", 5)
>>> coin.get_title()
'a gold coin'
>>> coin.cost
5
>>> coin.is_name("coin")
True

is_name() works even though it is not in item.py. It came from Unit.

You can ask Python about the relationship with isinstance(), which checks whether an object belongs to a class:

>>> isinstance(coin, Item)
True
>>> isinstance(coin, Unit)
True

The coin is an Item, and it is also a Unit, because every item is a unit.

Summary

You made a class that builds on another class. You learned that:

  • Every .py file is a module, and you can import from your own files.
  • class Item(Unit): makes Item inherit everything from Unit.
  • super().__init__(...) lets the parent class set up its part of the object.
  • A child class adds its own attributes and methods.
  • A getter is a method that returns an attribute.
  • isinstance() checks what class an object belongs to.
  • Clear parameter names are easier to understand by ear than single letters.
